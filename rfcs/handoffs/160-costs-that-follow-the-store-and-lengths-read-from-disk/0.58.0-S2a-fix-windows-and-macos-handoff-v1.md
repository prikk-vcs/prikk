# 0.58.0 S2a fix — two tests are platform-shaped (main is red on Windows and macOS), and the fixture is excluded from the crate

**Live 2026-11-15, and it goes FIRST, before S2b.** Main is red.

## What failed (CI run `43648586272`, on `b2202bd0`)

**1. S0's test, on Windows only:**
`patch_exchange::accept::tests::a_held_directory_moved_before_the_claims_refuses_and_records_no_claim`
(`accept/tests.rs:1031`, `unwrap_err()` on `Ok`). It has also been red since `cb1857d6`, in run `43644728256`.
- **Why:** P2b's held-directory check exists only on Linux and macOS. Windows keeps no table, so the check is always `Ok`,
  and on Windows `accept` correctly succeeds.
- P2b's own tests sit under `caller_tests`, which is gated to Linux and macOS. S0's test is in `accept/tests.rs`, and it is
  not gated.

**2. The corpus, on Windows and macOS:** `s2a_sync_seal_corpus::every_shape_seals_to_the_recorded_corpus`.
- **The architect diffed expected against actual for all eight shapes on both platforms. The only record that differs is
  `log-json.sha256`.**
- Every block id, RefState id, `log.sha256`, `pointer-index.sha256`, exit code and stdout line matches. **So sealing
  output is identical across Linux, macOS and Windows,** which is a result worth stating in the test's header.
- **The cause is the corpus's own text replacement of the repository path in `log --format json`.** The printed path is
  platform-shaped:
  - macOS resolves the temporary directory through `/private/var`;
  - Windows prints backslashes, escaped inside JSON.
