## Part A — one step to `ref complete` (60 min, report `0.51.0-step-1-A-report.md`)

`branch close` answer `--repair-tails` first, because the tail guard runs before the publication check.
`--repair-tails` then names `ref complete`. That is two steps.

**The fix:** when the tail the guard finds is a lead's torn record (the N3 state), these four commands name `prikk ref
complete <ref>` directly.
- **One mapping,** through the typed `PrikkError::IncompletePublication` path, as Part C of the 019 corrections set
  it. Never match message text.
- **A lead-free tail** keeps naming `--repair-tails`.

**Tests:**

- the lead-free control still names `--repair-tails`.

## Part C — `--keep-slot`: the way out of a lost generation log, chosen by the user (90 min, report `0.51.0-step-1-C-report.md`)

**Why.** For the trust policy and the received index, a lost generation log can leave two slots that fit two honest
histories (the H1/H2 twin, `row_14b_…`). Every reader refuses, rightly. Today the only way out is a backup. The user
knows which history is theirs, so let them say so, and see both first.

**The command:** `prikk compact --trust-policy --keep-slot a|b [--plan-only]`, and the same with `--received-index`.

**The ruling:**
- **Allowed only in the lost-log state:** the generation log names no live slot, and slot B holds data. That covers
  both the ambiguous state and the deduced one.
- **What it does:** it treats the chosen slot as live and compacts it into the other slot, exactly as an ordinary
  compaction does from a live slot. Then it records the generation.
  - **Before any write,** it saves the slot it overwrites, and the generation log, as one recovery run. These are
    `Replace` entries, in Q2b's order.
- **What `--plan-only` and every real run print first:**
  - for each slot, its entry count and its folded state: for the trust policy, the trusted maintainer key ids; for the
    received index, each ref and its tip;
  - for the trust policy, **the keys trusted in one slot and not in the other, by name**;
  - which slot prikk deduced, or *"ambiguous: prikk will not choose"*;
  - what the run would write and save.
  - **If the chosen slot differs from the deduced one,** the plan says so in one line.
- **Refusals,** each naming its way out, and each writing nothing:

| # | state or arguments | answer |
|---|---|---|
| K1 | the generation log records a live slot | refuse: *"the generation log names slot X; `--keep-slot` is only for a lost log"*, and name plain `compact` |
| K2 | lost log, ambiguous (the twin), `--keep-slot a` | a's fold is live; b is saved; restore is byte-identical |
| K3 | the same, `--keep-slot b` | b's fold is live; a is saved |
| K4 | lost log, deduced A, `--keep-slot a` | the same result as plain `compact`, with the save |
| K5 | lost log, deduced A, `--keep-slot b` | allowed; the plan says *"prikk deduced a; you chose b"*; b's fold is live |
| K6 | the chosen slot is damaged (does not decode cleanly) | refuse: the chosen slot cannot be read |
| K7 | the other slot is damaged, the chosen one is sound | allowed; the damaged bytes are saved byte for byte, and restore gives them back |
| K8 | the chosen slot holds no entries | refuse: *"slot X holds no entries; it cannot be the live slot"* |
| K9 | `--keep-slot` with `--pointer-index` | refuse, naming `prikk doctor --rebuild-pointer-index --plan-only`, because the ref log decides |
| K10 | `--keep-slot` with `--all` | refuse: name one container |
| K11 | never compacted (the log is empty, B is empty) | refuse: *"slot a is live; there is nothing to choose"* |
| K12 | a failpoint crash at the truncate | the recovery run is present, and restore is byte-identical |
| K13 | a write after `--keep-slot`, then a restore of its run | the restore refuses |
| K14 | `--plan-only`, in every row above | nothing written (hash of `.prikk/` equal) |
| K15 | the received-index twin (an older tip re-imported), `--keep-slot` | `branch list` shows the chosen slot's tips |
