## Part U4b (45 min, stop at 90; report `0.57.0-U4b-report.md`), before U2

**0. FIRST: `main` is red.** CI on `88e9bf8d` (run `42994804011`), the `stable` job:
`uncommit::tests::uncommit_raced_against_a_commit_ends_in_one_of_two_states_every_round` panicked at
`uncommit/tests.rs:773`, `expect("uncommit finished")`.
- **This is not U4's code.** It is S5b's store race test: `uncommit` met a lock conflict on all 2,000 attempts,
  because each retry is a `yield_now`. On a loaded CI runner, the racing `commit` held the lock longer than 2,000
  yields take.
- **The budget counts iterations, not time,** so the test's real assertions (two end states, no acknowledged commit
  lost) never ran in that round.
- **Fix the test, not the product:** bound both retry loops by a deadline (tens of seconds) with a short sleep between
  attempts, and fail with a message naming the round and how long the lock was held. Keep the 200 rounds and the
  lock-dropped red control (it must still go red).
- **Read the other race tests for the same shape** (an iteration-counted retry around a lock), and fix any you find.
- Report the CI run on the fix.
