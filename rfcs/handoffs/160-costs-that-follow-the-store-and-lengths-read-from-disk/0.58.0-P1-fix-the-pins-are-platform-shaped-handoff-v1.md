## What failed

**CI run `43586386310`, on `5a3f5b32`:** the job "Windows mutation test suite" fails at
`p1_sync_count_per_operation::each_operation_kind_counts_what_the_kernel_counts`
(`crates/prikk-cli/tests/commit_and_seal/p1_sync_count_per_operation.rs:318`). All 16 other jobs pass, macOS included.

| the pin (Linux) | 89 | 186 | 1 | 1 | 1 | 141 | 164 | 121 | 95 |

**Why:** a Windows directory has no sync (P1's report says so), so the counter there reads file syncs only. **The numbers
agree:**
- `commit`'s file share on Linux is 89 − 58 = 31. P1's RC1 measured 58 directory syncs when the file primitive stopped
  counting.
- The readers' one sync is a directory sync (`open_validated_child` on the worktree root).

macOS passes because its directory sync (`F_FULLFSYNC`) is counted as Linux's is. **The counter is right. The
expectation is not platform-shaped.**

## The rule

1. **Pin files and directories separately, per operation.** The report line (`sync-calls: N`) gains the split, for
   example `sync-calls: N (files F, directories D)`, from the counter's own two counting sites. The existing total stays,
   so nothing that reads it breaks.
2. **The file count is one number for every platform.** **The directory count is derived from the platform, not typed
   per platform:**
   - Linux and macOS: the measured value;
   - Windows: 0, because the primitive does not exist there.

   It is one expected table, with the Windows directory column computed from `cfg(windows)` and one comment saying why.
   If a Windows file count differs from Linux's, that is a finding, not a pin to edit: stop and ask.
3. **The `strace` agreement stays Linux-only,** as it is.
4. **The store-level pins in `caller_tests/sync_count.rs`** are `cfg(any(target_os = "linux", target_os = "macos"))`
   today. Leave them so.
5. **P1's review recorded that the readers pay one fsync.** That is a directory sync, so it is Linux and macOS only.
   Make the comment at the call (`layout.rs`) say so.

**The red control:**
- make the Windows directory column equal the Linux one: the test goes red on Windows CI (say so after the push);
- on Linux, drop the directory split from the report: the pin goes red.
