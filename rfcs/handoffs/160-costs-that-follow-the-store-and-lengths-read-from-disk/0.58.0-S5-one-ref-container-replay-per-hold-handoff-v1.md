`publish_body` (`refs/publication.rs:100`) reads each whole container once per publication. RFC 165 R1 cut that from three
reads to one. For a batch of N publications, that is N whole reads.

## The rule

1. **One mechanism: S4's, not a second one.** Kept decoded state on the hold's slot (`HeldDirectories`' `kept`), registered
   and released by the same hold, and absent outside one. **Say whether S4's kept-value slot extends to more than one value,
   and how,** without an index type or a ref type in `fsutil`.
2. **Never stale, with S4's rule:** identity, size and the last record re-checked at each use, and only the tail decoded.
   Two things differ from the object index, and the design covers both:
   - **Slots and generations.** The pointer index (and the received index) have slot A and slot B and a generation log.
     Compaction (`compact.rs:396` `compact_ref_pointer_index`, and the `_keep_slot` variants) switches the live slot. A kept
     copy must be of the **live slot as the generation log resolves it** (`resolve_live_slot`). A generation change means a
     full re-read. **Say whether the ref log has slots too** (there are `log-a` and `log-b` files), and treat it the same way.
   - **Who writes between this command's lock acquisitions.** List every ref writer and the locks it takes: `sync seal`,
     `seal`, `merge`, `branch`, `tag create`, `sync adopt-tag`, `bundle import --adopt`, `archive import`'s landing,
     `ref complete`, compaction, `doctor --rebuild-pointer-index` if it exists. One that takes the ref-container locks without
     the active lock can append between two of this command's publications, as `sync build` did for the object index.
     **A test:** another writer publishes a different ref between two of this command's publications, and the next
     publication sees it.
3. **The publication's checks are unchanged.** It still classifies against the current state: the CAS, `ensure_agreement`,
   the incomplete-tail rules (RFC 165), and P2b's held-directory check. Each is now asked of the kept, re-checked state
   instead of a fresh whole read. **Every existing publication-recovery test still holds** (`refs/tests/publication_recovery/…`).
   Name any that needed a change, and why.
4. **Damage and torn tails behave as a fresh read does today.** A kept copy that finds damage in the tail is dropped, and the
   call takes today's path.
5. **Platform:** with S4's identity, Linux and macOS (the W1 ruling). On Windows, today's whole read. The mechanism's tests
   carry that `cfg`.
