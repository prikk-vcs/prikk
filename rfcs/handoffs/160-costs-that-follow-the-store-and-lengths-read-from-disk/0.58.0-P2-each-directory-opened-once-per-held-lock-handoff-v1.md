# 0.58.0 P2 — each directory opened once per held lock, and the held directories checked before publish

**Live 2026-11-14, and it is next** (P1 accepted: `.git-exclude/reviewed/0.58.0-P1-review-v1.md`).

**The condition is owner-accepted**, from `.git-exclude/scratch/0.58.0-design-items-philosophy-check-v1.md`, P2. Fewer
opens, with handles anchored at the same root, are cleaner and no less safe. But a held handle can outlive its path.

## What P1 measured (the baseline)

**Inside a held lock, N objects cost `5 + 5N` syncs:**
- directories `4 + 3N`;

## Part P2a: open once per held lock (90 min, stop at 180)

**The rule:**
1. **Under one held lock,** each directory a writer needs is opened once, and its parent synced once, at the first use.
   Every later write under that lock uses the held handle. **The handles are anchored at the same `MutationRoot`, with
   no-follow on every component** (G1, `fsutil/contract.rs`). The conformance suite (`fsutil/tests`) passes unchanged.
2. **The durability promise does not change.** Exit 0 still means every entry a write relied on is durable.
   - **For each sync that goes away, the report names what makes the same entry durable instead.** Expected answer: the
     first open under the lock synced it, and nothing under the lock changes that entry afterwards.
   - **A directory created under the lock keeps its created-parent sync** (`ensure_child`'s `mkdirat` branch).
   - **If any sync cannot be accounted for that way, keep it and say so.** "A refactor can drop a durability property":
     the torn ref-name of 0.20.0 came from exactly this kind of change.
3. **Where the handles live is your design.** It might be the existing lock guard (`acquire_container_locks`), or
   `ObjectWriteSession`, or something beside them. **Lay out the options, with what each changes for its callers, and
   ask before building one** if they differ in a way the rule does not settle. **One mechanism for every writer that
   holds a lock:**
   - `commit`;
   - `seal`;
   - `bundle import`;
   - `sync accept`;
   - `sync seal`;
   - `archive import`.

   It is not a per-command cache.
4. **Windows:** the walk opens handles there too, with no directory sync. Say what the held handles change there: share
   modes, and whether a held directory handle blocks a rename or delete another process tries. Read CI's Windows jobs
   for this commit.
5. **`lookup_object_location`** (`foundation/index.rs:480`) has no production caller, and nine call sites in
   `index/tests.rs`. Remove it, and move those tests to the lookup production code uses. If that changes what a test
   tests, stop and ask.

**Rulings on the P2a question (2026-11-14, `.git-exclude/review-request/0.58.0-P2-part-a-question.md`):**
- **Option 1: a table of held directories on `MutationRoot`, filled and read only by the walk.** No caller passes
  anything.
- **A hold lasts from the command's first lock to its last release.** It is refcounted over every lock guard
  (`ActiveLock`, `RefLock`, `ContainerLockGuard` and every other guard type), and the table is cleared when the count
  reaches 0. That is the reading under which `seal` and `sync seal` gain: `ActiveLock` spans their 13 separate
  `objects.lock` holds.
- **Option 2 is not chosen.** It means about 90 changed call sites, and a forgotten site would be correct but silently
  slower. The pins would then be the only witness. **Option 3 fails "one mechanism".**

**The conditions on Option 1:**
1. **Every guard type registers. Enumerate them all** (a rule over a class: check every member). A test perturbs one
   guard's registration and shows the pins go red.
2. **No table outside a hold:** a test asserts the table is empty, or absent, when no lock is held, and again after the
   last guard drops.
3. **In-process directory removal or rename.** The architect's grep found that production `prikk-store` code renames
   only files (`linux.rs`/`macos.rs`/`windows.rs` atomic replace). Every `remove_dir_all` hit is in a test module, and
   `extract`'s `renameat` is in the extract target, not under `.prikk`. **Re-run that audit and list it in the report.**
   If any production site removes or renames a directory under `.prikk` while a hold is open, it invalidates the entry,
   with a test: removal under a hold, then a write, which lands in the new directory or refuses, never in the unlinked
   one.
4. **P2b's check runs over every entry in the table,** not over a separate list. That makes it the safety net both for
   another process's move and for a missed invalidation.
5. **Threads:** one `Mutex` on the table. Name any path where two threads write under one root at once today, and test
   that one.

**`lookup_object_location` (rule 5):**
- **Remove it.** It is `#[cfg(test)]`, so it ships nowhere, and a test of its refusal tests behaviour no shipped code
  has.
- **Move the eight tests that read the index through `replay_index`,** with nothing changed in what they hold.
- **Redefine the ninth (`tests.rs:299`) as the production behaviour:** a damaged index entry, then the production lookup
  falls back to a scan and finds the object. If a test already holds exactly that, delete the ninth and cite the one
  that does.

**It closes on P1's numbers:**
- the pins move to the measured truth, with the expected marginal of 2 file syncs per object and no directory sync per
  object;
- the operation table is re-measured, counter against `strace`, before and after;
- name the reduction per operation.

`bundle import` and `sync accept` are planeter's shape: give their per-patch numbers at 10 and 100 patches.

**The red controls:**
- restore the per-object walk: the pins go red;
- drop the created-parent sync for a new directory: name what catches it. **If nothing does, that is a gap: add the
  test.**

**CHANGELOG:** one `### Changed` line with the measured numbers per operation. Fewer syncs is a performance change a
user feels on disk. No output changes.

## Part P2b: the held directories are checked before publish (60 min, stop at 120)

**The condition** (owner-accepted). A held handle can outlive its path: a directory renamed or replaced by another
process during the command would receive writes that the command reports as done.

**Before it publishes** (the first ref or pointer write that makes the work visible), **the command checks each held
directory against its path.**
- **The check:** on Unix, device and inode via `fstat` of the handle against `fstatat` of the path, no-follow from the
  root. On Windows, the volume serial number and file id.
- **On a difference, it refuses before publishing:**
  - naming the directory;
  - saying it was moved or replaced while the command ran;
  - naming a typeable way out (re-run the command; `prikk verify`).

  Exit 1, nothing published.

  **What was already written into the moved directory** is content nothing names. `verify` counts it as unreached.
  Confirm that in the case table, and say what `verify` and `doctor` print.
- **One check per lock, not one per object.**

**First, the case table,** measured on the build. A test hook stops the command between its writes and its publish (a
failpoint or a barrier, as `wait_at_directory_create` does). Each row moves a held directory while it is stopped:

| # | what moves |
|---|---|
| 1 | nothing (the ordinary case) |
| 2 | the held directory renamed away |
| 3 | replaced by a new empty directory of the same name |
| 4 | replaced by a symlink to another directory |
| 5 | removed |
| 6 | an unrelated directory moved (must not refuse) |

**For each row:** the exit, whether anything was published, `.prikk`'s refs byte-identical, and what `verify` says
after.
- **If a row's right answer is not "refuse before publishing" (2–5) or "as today" (1 and 6), stop and ask.**
- **On Windows,** row 2 may be impossible while the handle is held. If so, say so from CI's Windows job, not from
  documentation.

**Then:**
- one test per row through the store, and one through the binary for row 2;
- **the red control:** skip the check, and rows 2–5 go red;
- **docs:** `durability-recovery.md` or `concurrency-locking.md`, wherever the held-directory rule belongs, gets one
  paragraph;
- **troubleshooting:** an entry for the new refusal;
- **CHANGELOG:** `### Changed` for the refusal.
