## Part 2 — A1: `prikk extract` for a ref or a block id (about 90 min, report `0.54.0-step-3-part-2-report.md`)

**The command:** `prikk extract --ref <ref|block-id> <dir>`. The CLI form follows `cat` and `tree`; propose the exact
syntax in the report.

1. **Anchoring (ruling 2):** the admitted anchor only (`AnchorTrust`, as `VerifiedWorktreeWrite`). Otherwise it
   replays from genesis.
   - **It never uses `Anchoring::ReadOnlyReport`.**
   - `cat` and `tree` keep theirs.
2. **The pre-walk:** Block envelopes only, measuring the distance to the nearest **admitted** snapshot. Past
   `CHECKPOINT_CADENCE`, it refuses by name, giving the distance found and `--allow-full-replay`. It runs before any
   Patch or Blob is read.
3. **Streaming (ruling 1):** every file at the anchor is written straight from its blob id, unless a later block applies
   `EditText` to it.
   - Binary files created or replaced after the anchor are written from their new blob id.
   - **Only text files edited after the anchor are held,** with their base.
   - **Say from source how a file whose path is renamed after the anchor is handled.**
4. **Write safety:**
   - `validate_no_path_collisions` over the point's paths, before the first write;
   - the target must not exist;
   - a temporary sibling `<dir>.prikk-extract-tmp`. If it exists, refuse and name it (ruling 3);
   - `rustix::fs::renameat_with(..., RenameFlags::NOREPLACE)` on Linux and macOS;
   - `MoveFileExW` without `MOVEFILE_REPLACE_EXISTING` on Windows, **pinned by a Windows test that CI's Windows job runs**
     (ruling 4);
   - **all-or-nothing:** a refusal or error leaves neither the target nor the temporary sibling, except after a hard
     crash.
5. **`provisional: yes|no`,** worded as `checkout` words it.
6. **Never writes into the repository:** no lock, cache, marker or worktree write. A test asserts the `.prikk/` tree is
   byte-identical before and after.
7. **Tests and controls:**
   - **output equal, byte for byte, to `cat --output` of every path that `tree` lists at the same point,** across text,
     binary, edited-after-anchor, renamed and deleted files, and with no extra files;
   - the collision refusal, shown red by removing the check;
   - the no-replace rename, shown red with a plain `rename` (Linux);
   - the pre-walk refusal, shown red by removing the bound;
   - **the trust rule:** a crafted unadopted-key block whose snapshot disagrees with its patches. `extract` writes what
     the patches give (full replay), not the snapshot. Shown red by passing `ReadOnlyReport`.

## Part 3 — A2: limits, the size report, JSON, and a pending claim (about 90 min, report `0.54.0-step-3-part-3-report.md`)

1. **`--plan-only`:** reports the point's file count, total bytes and `provisional`, and writes nothing. This is
   planeter's size-first report.
2. **`--max-bytes N` and `--max-files N`:** refuse the whole point, by name, before the first write.
   - **The documentation states** that they hold before the write, not before the cost.
   - **The pre-walk bound is the guard before the cost** for history depth.
3. **`--format json`** with `file_count`, `total_bytes`, `provisional`, and the resolved point (ref name or block id,
   target block id). It follows `tree`'s conventions.
4. **`--claim <claim-id>`:** a `RecognitionClaim` id, as `sync seal --claim` takes it. Its state is the claimed parent
   plus the claim's patches, through `derive_next_state_for_candidate` (read-only).
   - It needs the `StateRootEntry` + `TextCache` → files adapter, streaming under the same ruling.
   - **A dedicated `AnchorSite` name** for this read.
   - `--ref` and `--claim` are mutually exclusive.
   - **The case-collision refusal matters most here:** queued patches can hold a colliding pair that only `seal`
     rejects. Test that shape.
5. **Measured** (release build, idle machine, ≥2 samples, peak RSS of the process): shapes (a), (b) and (c) from your
   round-2 report, plus the pre-walk. **These figures go in `commands.md`** as the memory statement (ruling 1's form)
   and in the report. The architect uses them for planeter's letter.

## Part 5 — B2a: `prikk received remove <remotes/…> [--plan-only]` (about 90 min, report `0.54.0-step-3-part-5-report.md`)

As your B2a round-2 design, with:
1. **The lock and the reduction:** `compact_received_index`'s own lock and reduction, minus the target's key.
2. **The recovery-log save is unconditional:** both the slot and the generation log, every run.
3. **Refusals:**
   - `validate_received_ref`;
   - no such pointer;
   - a damaged index (the compaction precheck's text, naming this command);
   - the tail guards.

   **The exclusion list, tested:** `bundle import`, `archive import`, `archive export`, `compact`,
   `doctor --repair-tails`, and the recovery restore.
4. **The case table, both parities,** as your round 2. **Add the row** *removal, then re-import of the same name, then a
   recovery restore*: the restore refuses, because its meaning file changed.
5. **The kill sweep to 3B's standard,** at every fired write ordinal:
   - (a) `verify`/`doctor` report only what the table predicts;
   - (b) a retry reaches the uncrashed end state byte for byte;
   - (c) a recovery restore returns the pre-removal state byte for byte.

   **Count fired ordinals only.**
6. **End to end:** an import under an unadopted key makes `verify` fail. Then `received remove` makes `verify` pass,
   with B1's warning. Then the restore makes `verify` fail again.
7. **Text:**
   - `commands.md`;

   - the 0.52.0 Security addendum's B1 + B2a sentence;
