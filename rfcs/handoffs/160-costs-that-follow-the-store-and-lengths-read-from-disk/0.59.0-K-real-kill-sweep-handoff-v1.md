**Live 2026-11-24. Step 0 is closed.** The owner ruled K into 0.59.0 on 2026-11-18 (*"All your recommendations are accepted."*):
- *K, the real-kill sweep in our own suite (Linux), is built before P5 builds;*

The ROADMAP's crash-points row ("Crash points the assurance table finds no test for") holds the scope and the external evidence.

**Why it comes before P5:** P5 changes the order of syncs and appends, which is exactly what a real kill tests. The memory "a refactor can
drop a durability property" is why the sweep must exist, and be green, before that change.

**The external reviewer's word (057, 2026-11-18,
`.git-exclude/upstream/external-architect/receive/057-reply-056-yes-adapt-the-kill-sweep/README.md`):** we may adapt `sctrace.c`,
`probe25.sh`, `kill9.sh` and `lib053.sh` (in `receive/055-ack-0-58-0-released-verified/reproduce/`) under Apache-2.0. Each adapted file
carries *"adapted from the external review kit for prikk (reviews 053 and 055)"* and an SPDX header. **Their limits, to carry across or do
better:**
- x86_64 only (`orig_rax`; aarch64 needs `PTRACE_GETREGSET` and `x8`);
- a hand list of "mutating" syscalls (list what is counted, or count every one);
- the kill lands at syscall **entry** (also kill at exit, for the exact state);
- `SIGKILL` is process-wide and the ordinal counts across threads, so it is deterministic only while the writers are single-threaded.

**Their suggestion:** keep the C driver as the reference, and drive the kill from Rust in a Linux-gated test that `reference-check` can
name in the durability table.

## K1: measure and design (120 min, stop at 180)

1. **Run the reviewer's kit as it is,** on a release build of `main`: `probe25.sh` over `commit`, `seal`, a checkpoint `seal`, `sync seal` of
   a batch, `uncommit`, `doctor --repair-wal-tail` and `--repair-tails`. Each ordinal must end sound (`verify`, `doctor`, the command
   again, the content). **Record:**
   - the ordinals per command;
   - the wall time per command and in total;
   - what ended unsound, if anything. **Stop on an unsound ordinal:** that is a finding before it is a test.
2. **The writers 0.59.0 added or changed since 053:**
   - `doctor --remove-ref-candidates`, with its `Remove` recovery entry;
   - the W producers' refusals (they write nothing, but say so);
   - `tag create`'s new lock order;
   - and any other repair verb.

   Add them to the sweep, and say per writer what "sound" means: the case table's crash row.
3. **Kill at exit as well as at entry** (057's second limit): measure what it adds (new states reached, ordinals, time).
4. **The design:**
   - **The driver:**
     - (a) the C driver built in CI (a `cc` dependency and a build step);
     - (b) a Rust driver on raw `libc` (`ptrace`, `waitpid`), in a test-support crate or `prikk-ffi`, which is the one crate that holds
       `unsafe`;
     - (c) `nix::sys::ptrace`, a new dependency.

     **This is a dependency decision ("dependency is a decision"), so lay out each option's cost:** the crates it adds, the `unsafe` it
     adds and where, and MSRV.
   - **What is counted:** the hand list, or every syscall. Say what prikk issues today (`strace -c` on each writer).
   - **Architectures:** x86_64 only, said plainly, or aarch64 too (`PTRACE_GETREGSET`).
   - **Threads:** do the writers spawn any today (`strace -f`)? If none does, say so, and make the test refuse to run, naming why, the
     day one does.
   - **Where it runs, on the measured time:** every push (`ci.yml`), the release gate, or a scheduled job. **Time cost matters:** give the
     numbers that decide it, and a sampling scheme if the full sweep is too long for the place you propose (stride, seeded, every ordinal
     at the release).
   - **The assurance table:** which crash-point rows become "real kill (Linux)", with `reference-check` naming the test. **The Windows gap
     stays stated.**
5. **The report:** the measurements, the options with costs, and a recommendation per decision. **Nothing built.**
