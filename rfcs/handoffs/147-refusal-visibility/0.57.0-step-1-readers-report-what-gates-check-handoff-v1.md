# 0.57.0 step 1 — readers report what the gates check

**Live after step 0 closes** (part 0c accepted, its CI green). This is the ROADMAP 0.57.0 row's item (1), in the theme
"what we promised, and what reads wrong". Every part follows one rule from the owner's philosophy: **a reader never
reads cleaner than the check it reports on, and every finding names a way out the user can type, or it is not shown.**

Three parts, one sitting each, in order. One report per part: `.git-exclude/review-request/0.57.0-step-1-part-<n>-report.md`.
The working rule is as in step 0:
- every run in an R1 scope;
- `date` at the start and the end;
- a red control per new assertion;
- the 14 gates on the final commit;
- **stop and ask when the rule does not fit a case.**

## Part 1a: `doctor` reports every finding `verify` fails on (90 min, stop at 180)

**What step 0b found:** `verify` fails on three cache divergences and `doctor` was silent on all three. The commit-index
one is fixed (`PRIKK-DOCTOR-COMMIT-INDEX-DIVERGENCE`); `lifecycle-cache` and `merge-baseline` are not.

1. **First, the inventory, before any code:** every finding that makes `verify` exit non-zero (grep the verification
   report's fields and every place that sets the failing verdict). For each, give:
   - the `doctor` code that reports it today, or "silent";
   - its severity;
   - the way out it names.

   The commit-index row is the model.
2. **Then, for each silent row:**
   - a `doctor` issue with its own code;
   - a severity: `warning` when the finding is derived state that holds no history (as for the commit-index), `error`
     when history is affected;
   - a recommendation that names a prikk command.

   **If no command clears it, stop and propose the smallest one,** as 0b did. Do not build a new verb unasked.
3. **A test per new code,** through the binary: the finding is produced, `verify` fails, `doctor` names it and its way
   out, the named command clears it, and `verify` is clean. Add a red control.
4. **The `integrity-recovery.md` catalog** gets every new code, and `troubleshooting.md` gets every new message.

## Part 1b: `bundle preview` answers what `bundle import` will do about signatures (60 min, stop at 120)

**Today:** `sealed_by_signatures` covers the delivered tip's signatures only, while `bundle import` checks every Block
and RefState (`forged-publication-signature`). A preview can read `sound` for a delivery the import refuses (0.56.0
P2, external 046/049).

1. **Preview calls the importer's own admission check, the same function, never a second implementation.** It reports
   whether the import would refuse, and on which object.
2. **The shape, proposed for your report and not to be built until ruled:** keep `sealed_by_signatures` as it is (the
   tip's sealers). Add one field beside `import_class`:
   - `import_refusal`: the `refusal-v1` id the import would raise (for example `"forged-publication-signature"`), or
     `null`;
   - the text form prints the same refusal sentence the import would print, under a label.

   If the existing JSON readers (planeter, stikk) argue for another shape, say so. **Measure on the published 0.56.0
   and on the change** for a sound tip over a forged ancestor (the 0.56.0 smoke's §37f recipe).
3. **The cost:** the same as the import's own check (0.56.0 measured about 26 µs per signature). State it in
   `commands.md` and the CHANGELOG.
4. **Docs:** the 0.56.0 sentence saying the outcomes are for the tip only becomes the new behaviour.

## Part 1c: the ignored worktree record gets a way out, then a notice (60 min, stop at 120)

**Today:** a `.prikk/worktree.baseline` that is absent, empty, unreadable or names a missing Block reads as no record.
The next `commit`, `seal` or switch to another branch rewrites it, and until then the commit guard is off. `verify`
and `doctor` say nothing (the 9 `SILENT` matrix cells), and a no-op `branch switch <current>` writes no record.

1. **First, the way out.** `branch switch <the current branch>` writes the record when it is absent or ignored **and
   the worktree is clean against the tip.** Only then is "last written from the tip" true.
   - When the worktree is not clean, it writes nothing, as today.
   - Test both, through the binary.
2. **Then the notice:** a `doctor` warning naming the record and `prikk branch switch <current branch>`, shown only
   when that command would restore it (the worktree clean against the tip).
   - When it would not, there is no notice, because a warning with nothing to type is noise. The guard's state is then
     what `commit`'s refusals already cover.
   - Say in the report what the user sees in each case.
3. **The matrix:** say which of the 9 `SILENT` cells this turns into reported cells, by reading `matrix.py`'s shapes;
   no run is needed.

## Part 1d: one verb for every derived cache (60 min, stop at 120)

- **The rename:** the unreleased `--rebuild-commit-index` becomes **`prikk doctor [path] --rebuild-caches
  [--plan-only]`**. It rebuilds every derived cache that has a divergence check:
  - the commit-index, from the worktree bytes;
  - the lifecycle-state cache, by a full replay of the current branch's baseline from scratch;
  - any other the 1a inventory names.
- **Its contract:** the output names each cache and the count read. It runs under `commit`'s lock, `--plan-only`
  previews, and there is no recovery-log entry. Race it against `commit`, as 0c did.
- **The advice:** `doctor`'s and `verify`'s advice for the lifecycle cache names the verb and says "before your next
  commit" (a divergent lifecycle cache feeds `commit`'s incremental step, DC-64 §4–§5). The severity stays `warning`.
- **The test:** a stale lifecycle cache is found, rebuilt, and `verify` is clean. Add a red control.
- **The rename carries everywhere:** CHANGELOG, `commands.md`, `troubleshooting.md` and the doctor catalog.

## Part 1b2: the preview's shape, as ruled (60 min, stop at 120; report `0.57.0-step-1-part-1b2-report.md`)

- **The field: `import_refusals`, an array in the order the import checks.** It is `[]` when the import (without flags)
  would admit the delivery. Each entry is `{"id", "message", "object_type", "object_id"}`:
  - the class refusal first (`rollback` | `diverged` | `does-not-connect`, with the import's own sentence, and the
    object fields `null`);
  - then `forged-publication-signature` with its object.
- **Every entry comes from the import's own function,** the classification call as well as the signature check. No
  sentence is restated. `schema_version` stays `bundle-preview-v1`.
- **The text form:** one labelled line per entry, `bundle import of this delivery would refuse: <id>`, with the import's
  sentence indented. Nothing is printed when the list is empty.
- **Docs:**
  - `commands.md` gives the order, and says a class refusal is lifted by `--allow-non-fast-forward` and a signature
    refusal by nothing;
  - the CHANGELOG gets `### Fixed` (0.56.0's preview could read `sound` where the import refused) and an
    Output-changes line;
  - the 0.56.0 "tip only" sentence is replaced.
- **Tests through the binary:** an honest delivery gives `[]`; a forged ancestor gives one entry; a rollback gives one
  entry; a rollback over a forged ancestor gives two, in order. The real import of the last, with
  `--allow-non-fast-forward`, refuses with the second entry's sentence. Add a red control for the order.
