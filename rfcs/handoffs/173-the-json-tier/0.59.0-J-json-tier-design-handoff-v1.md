## J1: what is true today, measured (nothing designed) (90 min, stop at 120). DONE (accepted 2026-11-27; `.git-exclude/reviewed/0.59.0-J-part-1-review-v1.md`)

1. **The inventory: every `--format json` output**, from the code and checked on the binary. **One row per command (and per mode where
   the shape differs).** Each row gives:
   - the schema name and version field;
   - the top-level fields;
   - **every number field and its Rust type** (any that can be negative, fractional or above 2^53?);
   - **the deepest nesting**;
   - **every field that is sometimes absent and every field that is sometimes `null`,** and when;
   - **every enum-like string field and its full value set** (from the code).
   **Run each command at least once on a real repository and keep the output.** Say which commands have no JSON form at all.
2. **Refusals under `--format json`.**
   - **For every command with a JSON form:** does a refusal print a `refusal-v1`, on which stream, with which exit code?
   - **Make a table from the code (every `CliError` path reachable under `--format json`) and run at least one refusal per command.**
   - **Name each refusal that prints no `refusal-v1`, each exit code other than 1, and each id-field naming difference** (`refusal-v1`'s
     `refusal` against `bundle preview`'s `import_refusals[].id`).
   - **The unresolvable point:** `tree`/`checkout` exit 2 against the other readers' 1.
3. **`verify --format json`:** what the text form prints that the JSON does not. Findings with ids, their severities, `ways_out`, the
   ref-publication findings. **List each.**
4. **The three consumers' reads, checked against item 1.** For every field each consumer says it reads (stikk 024 §1, inklkunn §2.1,
   planeter §2):
   - **is it present today**, with the type and the absent/`null` behaviour they assume?
   - **Every mismatch is a row.** (Their own weaknesses, e.g. inklkunn's reading of a `refusal-v1` at a non-zero exit, are noted, not
     ours to fix.)
   - **Also list the text lines they parse** (their lists), and whether each has a JSON equivalent today.
5. **inklkunn's per-block paths:** what exists today.
   - Does any command give, per block, the paths touched and how (`log --format json`, `show`, `tree`, `diff` between a block and its
     parent)?
   - **Measure the cheapest existing way over the 2,000-block corpus** (`~/.pgtmp/arch-tools/inkl-s2.sh` makes one), in time and reads.
   - **Say which part of the cost is the `show` replay** (the 0.60.0 fix) and which part is per-call overhead.
6. **The report:** the tables, each fact with the command that showed it. **No design.**

## J2a: the promise, refusals and exit codes, designed (90 min, stop at 120). LIVE

**Start from J1's report and its review** (`.git-exclude/reviewed/0.59.0-J-part-1-review-v1.md`).

**For each item:**
- the options;
- a recommendation;
- the price (code, tests, docs, `### Output changes`);
- **what each consumer sees** (stikk, inklkunn, planeter, by their own letters).

**The owner rules after reading. Nothing built, no commit.** The consumers' standing constraints bind every option. **No shipped name is
renamed** (the J1 review, reading 1).

1. **What is promised, and where it is written.**
   - **A reference page** (e.g. `docs/src/reference/json.md`) with one section per schema:
     - every field, its type, and its presence class: **always present / present and nullable / absent by a stated rule**;
     - every enum-like field marked **closed** (a new value is a new schema version, or a notice first: choose) or **open** (a reader
       must accept an unseen value: say how it reads one).
   - **How a version moves:**
     - additive fields within `-v1`;
     - a removed field, a changed meaning or a presence-class change means `-v2`, alongside `-v1` for how long.
   - **Number bounds:** every number is an unsigned integer. **Promise below 2^53**, so JavaScript readers are safe, and say what
     happens to a value that would exceed it (none is reachable in practice: J1 §1.2).
   - **Name the outputs that are not promised** (if any), and why.
   - **The shipped spellings** (`Normal`/`Root`, `not_evaluated`, `prepo-`) are written down as they are, with **one rule for new
     names.**
2. **`refusal-v1` for every refusal of a command that has a JSON form** (J1 §2.2: 12 commands print none today).
   - On stdout, exit 1, the prose still on stderr.
   - **The ids each new one carries,** including planeter's asks:
     - `lock-conflict`;
     - `path-not-found`;
     - **the claim id, and the parent block id for `claim-parent-not-sealed`,** as additive structured fields;
     - whether the store changed.
   - **`bundle preview`'s `import_refusals[].id` against `refusal-v1`'s `refusal`:** an additive field, or documented as is. No rename.
3. **Exit codes, for J1 §2.4's real split.**
   - A **malformed** point or path (exit 2 in six readers, 1 in `log` and `worktree-status`);
   - a **well-formed absent** one (exit 1 everywhere, `refusal-v1` only in `cat` and `extract`).
   - **Recommend one rule for each class, for every reader.** Price the two readers that move.
   - **stikk reads exit 2 as its own usage bug** (M3): say what stikk sees under the rule.
   - **Also:** whether a usage error under `--format json` prints anything on stdout (today nothing); and §6.4, `bundle preview` exit 0
     with `import_refusals[]`.
4. **The three mismatch rows** (J1 §4.1):
   - M1, planeter's `received[].closed/current` and a received tip's signer;
   - M2, inklkunn's path union by key;
   - M3.
   For each: add, document, or tell the consumer.
5. **The report:** `.git-exclude/review-request/0.59.0-J-part-2a-report.md`.
