## The measurement

**What is known** (2026-11-14, the published 0.57.0, `~/.pgtmp/scope058b/probe18.log`): planeter's shape at 250 and 1,000
patches, `sync accept` reads 0.1–0.3 MB, makes about 10 fsyncs per patch, and peaks at **11 MB flat.** P2a has since taken it
to 4 syncs per patch.

**Measure on the published 0.57.0 and on main (`6766d273`), release builds:**
1. **planeter's shape at 10,000 patches.** The S5 artifact `~/.pgtmp/s5-10k-planeter-x.bin` (7.2 MB) is accepted by a fresh
   receiver.
2. **Large files:** an artifact carrying 100 MiB of 1 MiB binaries (`~/.pgtmp/s-probes/probe17.sh`'s shape, 100 blocks), and
   one carrying **a single 100 MiB file,** if `--max-object-bytes` allows it (say the bound you used).
3. **For each:**
   - peak RSS;
   - bytes read from the artifact;
   - store bytes read and written;
   - fsyncs (files and directories apart, with P1's counter);
   - wall time, saying whether the machine was idle.

**The decision rule, set before the numbers:**
- **If peak RSS stays within a few MB of a fixed size** (the 11–13 MB seen so far) **as the artifact grows from 7 MB to
  100 MiB:** memory does not follow the artifact. **P3 closes as "not built, by measurement",** with the numbers in the
  ROADMAP row.
- **If peak RSS grows with the artifact, or with its largest object** (state which: a 100 MiB single file peaking at about
  100 MB+ is "follows the object", not "follows the artifact"):
  - say where the memory is held (call sites);
  - stop;
  - the architect rules on streaming with P3's original conditions: one validator, pass 2 matching pass 1 per object, the
    interrupted-accept guarantee, and planeter's promise.
- **Compare with `bundle import`,** which already streams, on the same content. If `accept` is within its peak, say so.

**No code change** besides the R2 test. If you find a defect while measuring, report it, and do not fix it in this part.
