## What is wrong (measured 2026-11-18 on the published 0.58.0; the ROADMAP row "A reader, or the write-path precondition, reads …")

**One cause, three places.** A healthy repository reads as damaged, or as an incomplete publication, while another process publishes.
**Each place reads two or three of the ref pointer index, the ref log and the object index at different moments.**

1. **`verify` / `doctor`** (external review 055, `.git-exclude/upstream/external-architect/receive/055-ack-0-58-0-released-verified/reproduce/inflight.sh`
   and `inflight.txt`).
   - During a 300-claim `sync seal`, the `local-tag-trust` stage fails with `integrity error: ref heads/main names missing RefState …`,
     and `verify` exits 1: 177 of 274 runs on 0.58.0, 216 of 371 on 0.57.0. `doctor`: 15 of 40.
   - The reviewer's reading: the stage reads the pointer after the object scan. **Confirm or correct that from the code.**
2. **The write-path precondition** (`refs.rs`, `ensure_publication_precondition_with_replay`). It reads the pointer index, then the
   ref log, then opens the object snapshot.
   - **A `tag create` of a new tag between the first two reads** leaves a log record with no pointer entry.
   - `in_flight.rs:137` (`refusal_for_mismatch`, no pointer name) returns the generic refusal for that case, without the second read
     a pointer lead gets.
   - `sync seal` (`seal_from_accepted.rs:201` and `:295`) then rewrites the error through
     `incomplete_publication_refusal_naming_any_lead`, which re-reads and falls to `… use signer-backed seal retry`.
   - **Measured by the architect** with `~/.pgtmp/letters-0.58.0/f2-tag-race.sh` (301 claims, `sync seal` re-run up to 400 times
     beside a `tag create` loop; copy it into your logs):
     - **on tmpfs (`/dev/shm`), 3 of 3 runs:** 728–750 of 800 round lines refused;
     - **on disk, 7 of 7 runs:** 0.
   - **The site was found with a throwaway build** of the tag, in a detached worktree, never committed. It had `#[track_caller]` on
     `incomplete_publication_refusal`, `Location::caller()` in its message, and the original error appended at the two rewrite sites.
     All 736 were at `in_flight.rs:137`.
   - 0.57.0 on tmpfs: 780, plus 390 of its `tag create`s.
3. **`tag create --target heads/main`** refuses `--target ref heads/main RefState … is missing`: 37 times in one tmpfs run.

**All three fail closed, and the next run is clean** (`sync seal` alone completes; `verify` after the batch exits 0). They are older
than 0.58.0.

## Part RS1: inventory, baseline, design — nothing built (90 min, stop at 150)

1. **The publication order, from the code, not from this file.** For each publisher, write down in which order it makes its
   writes durable:
   - `commit`, `seal`, `sync seal`, `tag create`, `branch create`/`close`, `merge`, `sync adopt-tag`, `ref complete`;
   - the importers;
   - each repair verb that rewrites the pointer index, the log or the object index (`doctor --repair-index`, `--repair-tails`, the
     pointer rebuild).

   **Our working assumption is RefState object (container, then index), then the pointer, then the log.** Say where any publisher
   differs.
2. **The inventory: every site that reads two or more of the three** and draws a conclusion from comparing them. Classify by what it
   concludes, not by function name:
   - every `verify` stage;
   - `doctor`'s findings;
   - the precondition and its callers' rewrites;
   - `ref complete` (plan and apply);
   - every writer's resolution of a ref to a RefState or a Block (`--target`, `--from`, a merge's sides);
   - the readers (`log`, `show`, `tree`, `cat`, `checkout`, `extract`, `status`).

   **For each site:**
   - which reads it makes, in which order;
   - whether each read is a kept copy under a hold (S4/S5) and whether it is refreshed;
   - what a concurrent publication between its reads makes it conclude;
   - whether that conclusion is false.
3. **The baseline, on the published 0.58.0, tmpfs and disk,** n ≥ 3 runs each, state n/N:
   - the tag race;
   - 055's `inflight.sh` (the external reviewer's script; you may run it as it is);
   - **and one race per false-conclusion site that neither of those covers.**

   Counts by message.
4. **The design, under one rule.**
   - **Read in the reverse of the publication order** (log, then pointer, then objects, if item 1 confirms the order), so each later
     read is at least as new as the one before.
   - **A log that leads gets the same second read a pointer lead gets.** After the reorder it can only be damage, a legacy record, or
     a publisher that writes the log first (if item 1 finds one).
   - **For each site, name the change, or "already safe" with the reason.** Where a site cannot be reordered, say what it would need
     instead (a second read, or a retry of the whole check), and stop on that case for the architect.
5. **The conditions RS2 will close on, written out for each site:**
   - **(i)** no reader takes a lock;
   - **(ii)** every genuine state (an interrupted publication, a damaged pointer or log record, a missing object, a legacy record,
     candidate debris, a pending cleanup) is reported and refused **exactly** as on 0.58.0. List one perturbation per state: a
     hand-built state, the command, and the expected message and exit code;
   - **(iii)** store reads and peak memory unchanged against 0.58.0, at the S5 shapes (250 and 1,000 claims);
   - **(iv)** the races of item 3 on tmpfs and on disk: 0 false verdicts and 0 generic refusals for a healthy repository.
6. **What the release notes will say:** an `Output changes` entry per site (before, after), and a `### Fixed` section.

**Stop at RS1's report.**

### RS2a: the ref view (90 min, stop at 150)

1. **The write-path precondition:**
   - it reads L, then P (O stays last);
   - a log record with no pointer entry gets `refusal_for_mismatch`'s second read before the generic refusal;
   - the pointer-lead path is untouched.
2. **The rewrite** (`incomplete_publication_refusal_naming_any_lead`, `mismatched_lead_candidate`): L, then P, and it asks
   `in_flight::decide` for any lead it finds. **A running publisher is never named "interrupted: run `ref complete`".**
3. **`ref complete`'s plan** (`plan_ref_completion`, `evaluate_known_lead`), and **`resolve_worktree_baseline`:** L, then P.
4. **`verify` / `doctor`: one ref view at the top.**
   - It reads L, then P decoded once, then the object snapshots, and every stage takes the view's P.
   - **No new stage status, condition id, doctor code or JSON field.**
   - A pointer lead found in the view takes F2's existing path.
5. **Closes on:**
   - the tag race: 0 generic refusals;
   - 055's `inflight.sh`: 0 false `did not complete every stage`, with the in-flight finding kept;
   - `states.sh` identical;
   - `verify`'s reads at 250 and 1,000 claims, before and after.

### RS2b: the object-handle sites, mechanism A (120 min, stop at 180)

1. **LOCAL sites** (RS1 §4.6) open their snapshot after the pointer read.
2. **PARAM and session sites: one helper,** *"an id that a pointer named is declared missing only after a lookup at least as new as the
   pointer read"*.
   - **On a miss:** one more lookup in a view taken after the pointer read (the session's `ensure_current` where `&mut`, else a fresh
     index lookup), then today's message.
   - **A hit pays nothing.** The rest of a reader's snapshot keeps its point in time. Every site uses the helper, and no site copies it.
3. **Its test:** a truly missing id keeps today's message, exit code and `refusal-v1` id (`damaged-repository` for `cat`/`extract`);
   `states.sh` state 5.
4. **Closes on:**
   - the tag race: 0 `--target … is missing`;
   - `race-readers.sh` (both modes): 0 `points to missing RefState`, 0 `names missing RefState`, 0 false `local-tag-trust`;
   - the genuine `does not exist` lines unchanged;
   - reads unchanged at 250 and 1,000 claims.

### RS2c: the queue side, "A and not B", the two-read sites (120 min, stop at 180)

1. **Probes first:**
   - `classify`'s read order (the commit witness, the WAL, the pointer);
   - whether an unlocked reader can read a half-written pointer append as a torn tail.

   **If the second is seen, stop:** that is the container-lock judgement, a design question.
2. **The queue side** (`has_incomplete_active_cleanup_with_replay`, the witness reading, `active WAL metadata: missing for non-empty
   WAL`):
   - **an order where one suffices;**
   - **where none can** (a `seal` between its publish and its drain), judge the **active lock** with the existing judge:
     - **a holder that appears running** is in flight: the existing `PRIKK-VERIFY-REF-PUBLICATION-IN-FLIGHT`, `info`, with a sentence
       naming the running command and its pid from the active lock; for writers, the existing `another command is publishing …; run
       this command again when it finishes`;
     - **"does not appear to be running", "unknown" or no lock:** today's answer, exactly.
   - **`a queued commit you were told had succeeded … is no longer present at all` must never be printed beside a live writer.**
3. **The "A and not B" sites** (`received_tag_ids` / `sync tags`, `adopt-tag`, `accepted_but_unsealed_patch_ids`, `sync pending`): judge
   the candidate ref's `RefLock` with F2's `decide`. **If a site cannot know the candidate's ref name, stop,** naming the site.
4. **The two-pointer-read sites:**
   - `rollback-preview` and the digests take one shared P read;
   - `rollback-draft`'s compare stays a refusal. After the same prefix it says the ref moved while it planned, and to run it again.
5. **`decide` judges a lead by its identity** (added 2026-11-21, the RS2a review
   `.git-exclude/reviewed/0.59.0-step-0-RS-part-2a-review-v1.md`, ruling 1). The closure returns the lead's RefState id.
   - **B absent or agreeing:** `Gone`.
   - **B is A, holder running:** in flight.
   - **B is A, holder not running:** read the holder once more. Running gives in flight, else interrupted.
   - **B is not A:** in flight, with the pid if the last holder read had one, else the in-flight sentence without it.
   - **No loop.** Red controls with scripted ids for each arm. The four call sites and the F2 tests move with it. **Closes on:** the
     tag race on tmpfs, 0 generic `tag create` refusals (RS2a: 0–5 per run).
6. **Closes on:**
   - `race-readers-all.sh` (every line of a failing run, not only the first), mode `seal`, on disk and tmpfs: 0
     `ACTIVE-CLEANUP-PENDING`, 0 `no longer present at all`, 0 `active WAL metadata: missing`, 0 `seal stopped after it published`
     beside a live seal, 0 `object … references missing block patch`, and 0 `disagrees with the WAL …`;
   - `states.sh` states 1, 6 and 8 identical;
   - a race per "A and not B" site.

## Release-wide constraints on output (added 2026-11-19, from stikk 024; they bind RS, G, RH and every later 0.59.0 round)

stikk's answer to J's questionnaire (`.git-exclude/upstream/stikk/receive/024-what-we-rely-on-in-your-json.md`; the ROADMAP row
"J's consumer answers: stikk 024") names four things that break every released stikk. **Until J rules, no round may do any of them
without a stop to the architect first:**
1. **No negative or fractional number, and no nesting deeper than 16 levels, anywhere in a JSON report,** in fields stikk reads or
   not. stikk's reader refuses the whole document.
2. **No field switched between absent and `null`,** in either direction (stikk 024 §4 lists which fields are which).
3. **No new value in a closed set:**
   - `status`'s `queue.target_ref_status` and `queue.threshold_status`;
   - `worktree-status`'s `changes[].authoring` / `refusal`;
   - `bundle preview`'s `connectivity`, `conflict`, `effects[].kind` and `sealed_by_signatures[].outcome`.
4. **`prikk --version` keeps the shape `prikk X.Y.Z`,** and every refusal keeps its prose on stderr beside any `refusal-v1`.

**Added 2026-11-19, from inklkunn's answer** (`.git-exclude/upstream/inklkunn/receive/2026-11-19-what-we-read-in-your-json-and-0-58-0.md`
§2), three more, under the same stop rule:

5. **No new value in a field that decides a recovery or a verdict:**
   - `verify`'s `stages[].status` and `verdict.failed_conditions[].id`;
   - a `doctor` code that is not `info`;
   - a lock `kind`;
   - a `worktree-status` change `kind`.

   An unseen value stops inklkunn's recovery. **RS must not answer an in-flight publication with a new stage status or condition id
   unless the architect has ruled it.**
6. **`verify --format json` never prints `block_seals: null`.** Absent means an older prikk to inklkunn.
7. **Text that inklkunn parses keeps its shape unless the architect has ruled otherwise:**
   - `doctor`'s finding lines `<severity> [PRIKK-…]: …` (severity `error`, `warning` or `info`), its `recommendation:` lines, and its
     `issue summary:`, whose counts must add up;
   - plain `verify`'s `sealed-block <id>: <key>` lines, finding lines and trust counts;
   - `unlock`'s listing;
   - `ref complete --plan-only`, `uncommit` and its `--plan-only`, `doctor --discard-damaged-commits`;
   - plain `status`'s count lines, `key public`'s `public key:` line;
   - the stderr prefixes `unsupported format version: N` and `integrity error`.

   **A changed sentence after a stable prefix is fine.** A changed prefix, a new line kind in a listing, or counts that no longer add
   up are not.

**Added 2026-11-19, from planeter's answer** (`.git-exclude/upstream/planeter/receive/2026-11-19-reply-what-we-rely-on-in-your-json.md`),
three more, under the same stop rule:

8. **More closed sets:**
   - `extract`'s `point_kind`;
   - `verify`'s `stages[].status` outside `evaluated | failed | not_evaluated | halted`;
   - the `kind` of the content unions (`show`, `cat`, `checkout --patch-plan`);
   - a new `PRIKK-DOCTOR-UNREACHED-*` code.
9. **Fields that stay present:**
   - always present, `null` allowed: `extract-report-v1.claim_parent_block_id`, and `refusal-v1`'s `reason` for `extract` and the
     import refusals;
   - never dropped: `log`'s `sealed_by` and `parent_block_ids`, and `verify`'s `block_seals` and `publication_trust_issues`.
10. **`doctor`'s recommendations keep their `--flag` tokens** (planeter derives the repair to run from them). The substring
    `lock conflict` keeps meaning a lock conflict. No refusal prints `refusal-v1` with an exit code other than 1.

**A fact RS1 needs:** `verify --format json` has no findings list, so the in-flight id is text only (checked on 0.58.0 2026-11-19).
**RS does not add one;** that is J's question.

**RS1's item 6** (what the release notes will say) also lists, per site, whether the change touches any JSON output or any of these
text shapes, and checks it against all ten.
