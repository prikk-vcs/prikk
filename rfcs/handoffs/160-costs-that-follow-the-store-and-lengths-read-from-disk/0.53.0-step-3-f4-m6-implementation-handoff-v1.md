## Part 3A — F4: the cold `commit` baseline from the nearest trusted checkpoint (90 min)

### The change

- **`anchor_trust.rs`:** a new `AnchorSite::Baseline` (with its `name()`, `"baseline"`).
- **`block_state/anchored_parent.rs`:** `anchored_parent_state` and `AnchoredParent` widened to `pub(crate)`. **No logic
  change.**
- **`lifecycle_cache/incremental.rs`, `resolve_baseline_state_with`, in this order:**
  1. **Forced reanchor:** a readable cache whose counter has reached `CHECKPOINT_CADENCE`, **whatever its horizon**, gets
     `replay_derived_state` and persists `0`. This is checked first.
  2. **Warm:** same horizon, a same-baseline hit or an eligible step. As today, persist counter + 1.
  3. **Anchored:** `anchored_parent_state(…, AnchorSite::Baseline)` returns a state.
     - It persists **the loaded cache's counter + 1**, same horizon or not.
     - With no readable cache, it persists `0`.
  4. **Otherwise:** `replay_derived_state`, persist `0`.
- **The rule, in the code's own comment beside DC-64 §5's:** the counter counts baseline resolutions since the last
  **full** derivation. Only `replay_derived_state` resets it. RFC 159 ruling 5: the reanchor and `verify_divergence` are
  never anchored.
- **`verify_divergence` is not touched.**
- **`merge-evidence`'s baseline** (`merge/evidence.rs`, `patch_algebra/evidence.rs`) **is not in this part.** It stays
  RFC 159's open remainder.

### Answer from source, in the report

- **The horizon.** `anchored_parent_state` takes a parent block but no `horizon_id`. State how its result honours the
  baseline's horizon, with a citation. If a lineage's horizon can be other than its first block, the identity control
  below includes one. If it cannot, cite why. **If the anchored derivation can disagree with `replay_derived_state`
  under some horizon, stop and ask.**
- **Where the anchor's kinds are authenticated:** `validate_snapshot_manifest`'s state-root recomputation
  (`snapshot.rs:181-213`; each leaf includes the kind, `state_root.rs:29-39`). The comment cites this. It does not cite
  `snapshot_files_from_manifest`, which is a reader (2A review v2, C-1).

### The read gate

- **`test_gates/store_size_independence.rs`:** the `one-file commit` row moves from `FollowsContent` to `Flat`, and its
  F4 finding is removed.
- **Measured on a release build at 1, 16 and 64 MiB stored:** a one-file cold commit's bytes read, today (the parent
  commit) and after. The design round measured about 8 KB flat. Show the numbers.

### Controls, each shown red first

1. **Identity.** At the `commit` baseline, the anchored state equals `replay_derived_state`, field for field, including
   tombstones and `seen_ids`. Check every block of a history with renames, restorations, merges and text edits, using
   stack A's corpus or its equivalent. **Perturbed** (for example, skip the id-only walk's tombstones), it fails.
2. **The site.** Removing the anchoring at `Baseline` turns this part's own tests and the gate row red, and nothing of
   stack A's. The per-site counter shows `baseline` consulted.
3. **The forced reanchor is full.** With an admitted anchor available and the counter at `CHECKPOINT_CADENCE`, the
   result comes from `replay_derived_state` and `baseline` is not consulted. **Perturbed** to anchor it, it fails.
4. **F4-4, the counter.** Run 200 baseline resolutions alternating a horizon switch (branch switch) and a commit, with an
   anchor available throughout. At least 3 full derivations happen, counted under `test-support`. **Perturbed** so that
   an anchored derivation persists `0`, the count is 0 and the control fails.
5. **No anchor, today's behaviour.** With no adopted signer, or an empty verified record, the result is a full
   derivation. **Over a damaged untouched historical blob, a cold `commit` still refuses,** as today.
6. **F4-2, the exception, pinned:**
   - a damaged untouched blob below an admitted anchor: a cold `commit` succeeds, and `verify` reports the damage;
   - the same damage, with the commit **editing that file:** it still refuses.
7. **`diff` writes nothing.** A cold `diff` (`CacheWrite::Never`) on the anchored path leaves `.prikk/` byte-identical.
8. **`verify` is never anchored.** Run a full `verify` with an anchor available: `baseline` is not consulted.
9. **Commit kill sweep.** Kill a cold anchored `commit` at every write ordinal. Afterwards, `verify` is clean, or names
   the interrupted state with its existing recovery. A rerun of `commit` gives the same result as an uninterrupted one.
   Report n/N.

### The case table (the case-table rule)

- **Rows, the states:**

  - a damaged snapshot manifest;

  - an unadopted signer;

- **Columns:** the cold `commit` (anchored and no-anchor), the forced reanchor, `seal`, `verify`.
- **Each cell:** today's outcome and the new outcome.
- **Every cell equal to today, except F4-2's, which is stated as the owner's exception.** Any other difference: stop and

## Part 3B — M6: one read of the queue per commit, the full check kept (60 min)

### A correction to the 2B review, from source

The 2B review said `append_patch_and_witness` should *"fold the one new record it already holds."* **That is right only
when the witness is valid and current.** `fold_running_hash` (`commit_boundary/witness.rs:232-253`, RFC 166 §13 item 2)
folds **every** sound record the witness does not cover. When the witness is absent or damaged, `covered_through` is
`0` and the whole queue is folded (`witness.rs:265-268`). **Folding one record there would write a wrong running hash.**

### The change

- **`Wal::append_patch` gains a crate-internal sibling** that returns the records its one `replay()` already read,
  beside the seq. For example, `append_patch_reporting(&self, envelope) -> Result<(u64, Vec<WalRecord>)>`, giving the
  records before the append plus the appended record, or the records as they are for an idempotent retry.
  - `append_patch` delegates to it, so its signature and behaviour are unchanged for every other caller.
  - **All four facts and every refusal stay exactly as today:** the clean tail, no damaged record anywhere, the next
    seq, and the idempotent retry.
- **`append_patch_and_witness`** folds over those records. The second `wal.replay()` (`witness.rs:271`) is removed.
  `fold_running_hash` is unchanged.
- **The whole-read guard's `wal-replay` row stays `Intentional`.** Its reason is sharpened: *the append re-checks every
  queued record before stacking another on it.*

### The read gate: a queue axis

- **`Axis::Queue`** at 100, 800 and 3,200 queued commits, with the `one-file commit` row on it marked
  `Expectation::FollowsContent`.
- **The finding says why:** the append's integrity check over pending work, kept by the owner's decision of 2026-10-15.
- **Its ceiling is sized from the measured single replay,** so a return to two replays fails the gate. Show the
  arithmetic.
- **If the existing `FollowsContent` floor (`large >= small + 8 MiB`) cannot hold on a queue axis,** propose the
  smallest honest form and stop and ask.

### Controls, each shown red first

1. **Same running hash, every witness state.** For each witness state, the witness written by the new path is
   byte-identical to today's two-replay path, over the same queue:
   - valid and current;
   - valid and behind (a queue partly written by an older binary, or a test-support append that wrote no witness);
   - absent;
   - damaged;
   - an idempotent retry.

   **Perturbed** to fold only the newest record, the absent and behind cases fail.
2. **The ceiling.** Restore the second replay, and the queue-axis ceiling fails.
3. **Interior damage still refuses.** Corrupt queued record 3 of 800. `commit` refuses, and the message names `doctor`
   and `--discard-damaged-commits` as today.
4. **A stale fold is caught.** Make the fold use a stale record, and `verify_running_hash` fails.
5. **Commit kill sweep** at every write ordinal, n/N, as in 3A.

### The case table, both parities

- **Rows:** a torn tail, a damaged interior record, a damaged last record, a witness mismatch, a witness absent or
  damaged, a concurrent writer, an idempotent retry.
- **Columns:** `commit`, `seal`, `rollback-draft`, `doctor`.
- **Each cell:** today and new. **Every cell equal to today,** stated.

### Measured

Commit time and bytes read at 100, 800 and 3,200 queued commits, today and after, on a release build, three samples
each. The design round measured about 2.71 ms dropping to 1.24 ms at 3,200.

### Docs

Grep `docs/` for what a commit costs with a long queue. Report the hits and any change.
