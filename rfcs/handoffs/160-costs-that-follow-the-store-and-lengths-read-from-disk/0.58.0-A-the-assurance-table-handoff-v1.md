# 0.58.0 A — the assurance table under the durability page

**Live 2026-11-17, and it is next.** B′b is accepted (`.git-exclude/reviewed/0.58.0-B-prime-part-b-review-v1.md`). **A is the last
item before the 0.58.0 cut.**

**What A is** (from external note 039, owner-authorized 2026-11-04; the ROADMAP's 0.58.0 row): under the durability page, a
table with **each crash point:**
- the test that holds it, by name;
- the kind of test;
- the CI platforms that run it.

The page also says **what each kind proves and what it does not.** It is not a crash matrix. **A gate fails if a cited test
name disappears.**

**Its conditions,** owner-accepted 2026-11-12 (`.git-exclude/scratch/0.58.0-design-items-philosophy-check-v1.md`, A):
1. **The rule goes into an existing gate,** `reference-check`, not a sixteenth.
2. **The page says what the gate checks:** that a cited test exists, **not** that it still asserts the property.
3. **The platform column comes from each test's `cfg`, never typed by hand.** cfg absence is not portability.

**Two parts:**
- **A1:** inventory, and the platform derivation, 90 min. **Stop if the derivation needs a choice.**
- **A2:** build, 90 min.

One report per part: `.git-exclude/review-request/0.58.0-A-part-<1|2>-report.md`. The working rule is P2's.

## A1: inventory, and how the platform column is derived (nothing built)

1. **The crash points.** List each one that `durability-recovery.md` (and the pages it links) states a behaviour for: the
   object append, the index, the WAL, the ref log and pointer index, the received index, the trust policy, the archive
   import journal, the verified-blocks record (S6), and `sync seal`'s five rows (S2a). For each, name the test that holds it,
   and its kind:
   - a real kill (`SIGKILL`/`abort` of the binary);
   - a failpoint (an injected error at a named point);
   - a byte-level state built by hand;
   - a unit test of the recovery function.

   **A crash point no test holds is listed as such.** Do not write a test in A. A missing test is a finding for the
   architect.
2. **What each kind proves, and does not,** in one or two sentences each. For example, a failpoint proves the recovery from
   the state the code would leave at that point; it does not prove the operating system leaves that state after a power cut.
3. **The platform column.** A test's platforms are its `cfg` **combined with the CI jobs that run its suite.** cfg absence
   says only that it compiles everywhere.
   - Read `.github/workflows/ci.yml`: which jobs run which test targets, on which OS. The Windows and macOS mutation
     suites, the stable Linux job and msrv each run some subset.
   - **Propose how `reference-check` derives the column:** parse the test's `cfg` (the `mod` gates included) and intersect
     it with a job map read from the workflow, **not typed into the gate.**
   - **If reading the workflow to derive the job map is fragile** (matrix expansion, `--test` filters), say what the
     smallest honest alternative is, and **stop and ask.**
4. **The gate's rule, as it will be written:**
   - every test name the table cites exists, as a `fn` in a test module that the derived platforms say is built there;
   - the platform column equals the derivation;
   - a missing name or a mismatch fails `reference-check`, naming the row.

## A2: build (after the architect reads A1, or at once if A1 needed no choice)

- **The table under the durability page,** generated or hand-written: say which. If hand-written, the gate checks it. The
  "what each kind proves" paragraph, and **condition 2's sentence, verbatim in spirit:** "the gate checks that each cited test
  exists and where it runs, not that it still asserts the property".
- **The rule in `reference-check`.**
- **The red controls:**
  - rename a cited test: the gate fails, naming it;
  - type a wrong platform into the table: the gate fails;
  - put a `cfg(unix)` on a cited test whose row says Windows: the gate fails.
- **The gate's time is stated** (time cost matters): before and after, on the gates' run.
- **The crash points no test holds** go into the report and onto the ROADMAP as a candidate row. They are not fixed in A.
- **CHANGELOG:** a `### Changed` line for the docs page. **No user-facing behaviour changes.**
