## What the measurement found (main and 0.57.0 agree)

| shape | `sync accept` peak | `bundle import` peak |
|---|---:|---:|
| 10,000 small patches (7.4 MB) | 52 MB (7.0×) | — |
| 100 × 1 MiB (105 MB) | 411 MB (3.9×) | **12 MB** |
| one 100 MiB file | 606 MB (5.8×) | 405 MB (3.9×) |

**Three copies are alive at once.**
1. The whole artifact in one `Vec` (`prikk-cli/src/sync.rs:222` `read_bounded_file`).
2. Every object decoded into an owned envelope (`decode_exchange_artifact` → `decode_envelope_section`, `artifact.rs:322`),
   kept until the end.
3. **A further ≈2× that appears after the repository is opened and before the first object write.** It sits in `accept.rs`'s
   phases C and D, between `ObjectReadSnapshot::open` (the closure check) and `ObjectWriteSession::open` (`accept.rs:333`).
   **Its allocation is not identified.**

## P3a: find the memory, then design (90 min, stop at 180). Nothing is built

1. **Attribute copy 3 first.** Use the same probe counting allocator F0 used: a detached worktree, never committed, the
   permission layer respected, on the b100 and s100 shapes. Name the call sites holding it.
   - **If it is in the validation phases** (the closure check, signature checks, author-key handling), streaming the decode
     alone does not remove it. Say what does.
2. **The design, reusing `bundle import`'s two-pass shape, with no second decoder.**
   - **Pass 1** reads the artifact once, as frames, and validates without keeping the objects' payloads. The author keys sit
     at the artifact's end, so pass 1 must read the whole artifact before signatures can be checked. Say how `bundle import`
     handles the same order.
   - **Pass 2** reads it again and writes, matching pass 1 object by object (the two-passes rule: a mismatch refuses, never
     writes on).
   - **The artifact is read from the file, not held whole.** Say whether a pipe or stdin input exists today. If it does, a
     second read is impossible, so say what happens.
3. **Fixed, and stated as the design's invariants:**
   - the artifact format;
   - planeter's write order and exit 1 for a write error;
   - **the state a killed `accept` leaves**, with the case table re-checked against `sync.md`'s guarantee (an interrupted
     accept never leaves a dangling reference, and a re-run finishes it);
   - every refusal `accept` raises today, with the same message, before the first write.

   List them from the code, the way S2a's checklist did, with the test that holds each.
4. **Claim no more than it delivers.** Memory will follow the largest object, not the artifact: one 100 MiB file stays several
   times its size, as `bundle import`'s 405 MB does. The docs and the CHANGELOG say exactly that.

**Stop at P3a's report** if copy 3 needs a choice the rules do not settle. Otherwise say so, and P3b builds.

**The gate (the architect's re-review, `.git-exclude/scratch/0.58.0-dev-team-recommendations-re-reviewed-v1.md`, §2–§3): stop
at P3a in any case, and do not start P3b until the architect has read P3a.** If copy 3 needs more than `bundle import`'s
two-pass shape, P3b's scope goes back to the owner, and the alternative is a lower default bound for `sync accept` in 0.58.0.

## P3b: build, and close on the numbers

On the P3 measurement's shapes, release builds, against the published 0.57.0 and `d34757a0`:
- **peak RSS no higher than `bundle import`'s on the same content:** about 12 MB for 100 × 1 MiB, and flat across 25, 50 and
  100 MiB of small objects and 10,000 patches;
- **one 100 MiB file no worse than `bundle import`'s 405 MB;**
- the artifact is read at most twice (state it);
- store reads and writes, and file and directory fsyncs, unchanged;
- planeter's write order and exit code unchanged, with a test through the binary that a write error mid-accept exits 1 and
  leaves the state the case table names;
- `sync accept`'s existing tests unchanged (name any that needed a change, and why).

**The red controls:**
- keep the decoded objects until the end: the RSS pin goes red. Pin it by a count of live decoded objects or bytes, not by
  RSS;
- pass 2 diverges from pass 1 (a frame changed between the reads): the refusal fires before any write;
- write claims before blobs: planeter's order test goes red.

**Docs:** the sync guide on `accept`'s memory, one sentence that states the largest-object bound. **CHANGELOG:** `### Changed`
with the measured peaks before and after.

**After P3:** P4 (the borrowed decode), then B′, A, and the cut.

## P3b: live 2026-11-17, after the architect read P3a (`.git-exclude/review-request/0.58.0-P3-part-a-report.md`)

**The gate passes.** Copy 3 is two clones made for the batch admission wrapper (`ordered`, `accept.rs:362`, and
`admit_carried_signatures`'s own `envelope.clone()`). Admission per frame through `CarriedSignatureAdmitter::admit_one`, which
`bundle import` already uses, removes both. Nothing needs more than `bundle import`'s two-pass shape, so the scope does not
go back to the owner.

**Rulings:**
1. **Lock A: take the lock after the header, before pass 1, as `bundle import` does.** That keeps two reads and one
   mechanism. Today's split (the early read-only key check, and the re-check under the lock, row 5) becomes **one decision
   under the lock.** Say which of today's two checks goes, and keep the test of a key recorded concurrently: it now cannot
   happen during pass 1, and the test should say so.
   - **The visible change:** a second writer can now meet a lock conflict during validation too. It is added to planeter's
     release-letter points.
2. **The order the tests pin is kept,** by deferring each patch's signature result to after the digest and closure checks,
   as P3a proposes.
   - **List every other refusal order that changes for an artifact with more than one fault,** in P3b's report. Each
     single-fault artifact keeps today's message.
3. **`decode_exchange_artifact` stays only as `cfg(test)`/`test-support` fixture code,** built on the same per-frame
   primitives, never reachable from `accept`, and named so the reader sees what it is. A test that `accept` does not call it
   (a symbol or reachability check, or the counter below) holds that.
4. **The frame primitives are hoisted unchanged** out of `bundle.rs` into one module both formats use. `admit_carried_signatures`
   is deleted if `accept` was its last caller (P3a: it was).
5. **One large object:** close at `bundle import`'s floor on the same file, 405 MB for s100. **If accept ends above it,**
   explain the difference: P3a saw three `encode_envelope_file` copies in accept against two in the bundle. A store write path
   that holds an object three times is RFC 158's, and it is recorded there, not fixed here.

**It closes on P3a §6's numbers,** against the published 0.57.0 and `8ce08064`, release builds:
- b25, b50, b100 and p10k flat at about 12 MB;
- s25 and s100 at `bundle import`'s floor;
- writes and fsyncs unchanged;
- artifact reads ≤ 2× plus 8 bytes per frame.

**Plus:**
- the invariants table (P3a §4) held, test by test, with row 12 new;
- the case table (P3a §5), with **the write-error test through the binary** (exit 1, the state the table names);
- **planeter's order test through the binary:** patches and blobs, then AUTHOR key material, then tags and claims, each
  preceded by what it names.

**The red controls** (P3a §6):
- keep the decoded objects: a live-decoded-bytes counter goes red, not an RSS figure;
- pass 2 diverges (the bundle's between-passes hook): row 12 refuses before that object is written;
- claims before blobs: the order test goes red.

**Docs:** the sync guide's sentence on `accept`'s memory (the largest object, not the artifact), and the interrupted-accept
paragraph re-read. **CHANGELOG:** `### Changed`, with the peaks before and after.
