# 0.59.0 K — a real kill of every writer, in our own suite (Linux), before P5

**Live 2026-11-24. Step 0 is closed.** The owner ruled K into 0.59.0 on 2026-11-18 (*"All your recommendations are accepted."*):
- *K, the real-kill sweep in our own suite (Linux), is built before P5 builds;*
- *its round decides where it runs, on measured time;*
- *adopting `strace` or a small ptrace driver is that round's dependency decision.*

The ROADMAP's crash-points row ("Crash points the assurance table finds no test for") holds the scope and the external evidence.

**Why it comes before P5:** P5 changes the order of syncs and appends, which is exactly what a real kill tests. The memory "a refactor can
drop a durability property" is why the sweep must exist, and be green, before that change.

**The external reviewer's word (057, 2026-11-18,
`.git-exclude/upstream/external-architect/receive/057-reply-056-yes-adapt-the-kill-sweep/README.md`):** we may adapt `sctrace.c`,
`probe25.sh`, `kill9.sh` and `lib053.sh` (in `receive/055-ack-0-58-0-released-verified/reproduce/`) under Apache-2.0. Each adapted file
carries *"adapted from the external review kit for prikk (reviews 053 and 055)"* and an SPDX header. **Their limits, to carry across or do
better:**
- x86_64 only (`orig_rax`; aarch64 needs `PTRACE_GETREGSET` and `x8`);
- a hand list of "mutating" syscalls (list what is counted, or count every one);
- the kill lands at syscall **entry** (also kill at exit, for the exact state);
- `SIGKILL` is process-wide and the ordinal counts across threads, so it is deterministic only while the writers are single-threaded.

**Their suggestion:** keep the C driver as the reference, and drive the kill from Rust in a Linux-gated test that `reference-check` can
name in the durability table.

**Three parts:**
- **K1** measures and designs, and builds nothing. It is DONE and accepted 2026-11-24.
- **K2** makes `--recovery-restore` finish its own interrupted writes. That is K1's F1, widened.
- **K3** builds the sweep.

- **K4** makes `init`'s format marker crash-safe and never relabels a repository; `format upgrade` restores a lost marker.
- **K5** closes K3's small items.
- **K6** makes the key files crash-safe, and lets `setup` finish its own interrupted run.
- **K7** makes the unreadable-key and finishing sentences say what was checked.

One report per part: `.git-exclude/review-request/0.59.0-K-part-<1|2|3|4|5|6|7>-report.md`.

## K2: a restore finishes its own interrupted writes (60 min, stop at 90). DONE (`db0b339f`, accepted 2026-11-24)

**Accepted** (`.git-exclude/reviewed/0.59.0-K-part-2-review-v1.md`):
- `Remove` and `Cut` are built, and the `Cut` defect is a released `### Fixed`.
- **`Replace` is ruled (D).** Item 3's rule below is withdrawn: with only `new_hash` recorded, it would truncate a later ordinary write
  away. The ROADMAP row carries (A).


**The rule:** *`--recovery-restore` recognises every state its own interrupted writes can leave, and finishes it. Any other state refuses
as today.* It applies in `recovery_log/restore.rs`, to the conditions and the done check, on every platform.

1. **`Remove`:**
   - **The state:** the path holds a prefix of the removed bytes, empty included. That is this step's interrupted recreation.
   - **The restore** writes the bytes whole from offset 0 and finishes.
   - **The refusal sentence** (`exists again, with other bytes than the repair removed`) stays for any other bytes only.
2. **`Cut` (the restore appends the removed bytes):**
   - **The state:**
     - the length is past the entry's offset and short of offset + removed;
     - the prefix hash holds;
     - the bytes after the offset are a prefix of the removed bytes.
   - **The restore** appends the rest. A kill inside one `write` of more than a page can leave this, which a ptrace sweep never reaches.
3. **`Replace` (an overwrite at 0, then a truncate):**
   - **The state:** the overwrite is done and the truncate is not. The first `len(removed)` bytes are the removed bytes, and the file is
     longer.
   - **The restore** truncates. Note that a `--rebuild-pointer-index` run is sound today only because its saved bytes are a byte prefix
     of the newer file (the architect's sweep, 61 and 63 ordinals).
   - **A partly done overwrite** (the removed bytes up to k, then the newer bytes from k) cannot be proven from the entry, which holds only
     `new_hash`. **Say whether it is reachable, and if a fix needs an entry format change, stop with the options.** Do not change the
     format without a ruling.
4. **Is this a released defect?**
   - **Construct a `Replace` whose saved bytes are not a prefix of the newer file:** a compaction over a deduced live slot, the commit
     witness, or a trust-policy slot.
   - **Sweep its restore** with the K1 kit on this build and on the published 0.58.0 (`~/.pgtmp/rel-0.58.0/x/prikk`).
   - **If 0.58.0 refuses for good there,** it is a released defect and goes in `### Fixed`.
   - The `Remove` arm is unreleased (G2d) and folds into G2d's entry.
5. **Tests:**
   - **Each torn state is built directly** (bytes written to the file, no ptrace), so they run on Linux, macOS and Windows. Each test
     restores and asserts the file's bytes.
   - **The cases:** `Remove` at 0 bytes and at a middle prefix; `Cut` at a middle prefix; `Replace` overwritten and not truncated.
   - **And one of each of these, which must still refuse:** a non-prefix `Remove`, a `Cut` with a changed byte, and a `Replace` changed by
     a later write.
   - **A red control per arm:** the old condition makes its test red.
   - **The K1 reproducer `rr34.sh` at ordinal 34 ends restored.**
6. **The rules as in step 0:**
   - 15 gates;
   - a final build from the committed tree into a fresh target directory;
   - stage by path;
   - the ten output constraints. The changed `no` line is text, and no JSON moves.
