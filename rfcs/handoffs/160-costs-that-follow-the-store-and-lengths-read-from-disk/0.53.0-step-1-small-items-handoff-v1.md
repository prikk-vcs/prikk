## 1. `trust maintainer check`'s "not trusted" exit travels through `run()` (about 25 min)

- **Today:** the arm in `crates/prikk-cli/src/main.rs` calls `std::process::exit(1)` after printing the answer. That
  skips `main`'s epilogue (`warn_anchor_fallbacks`) for this one answer. It is harmless today (step 1 Part D review),
  but anything later added to the epilogue would be skipped silently.
- **Wanted:** one mechanism that carries *"a negative answer: exit 1, no `error:` line"* back through `run()` to `main`,
  so the epilogue runs on every path.
  - **`commands.rs` rules out a fourth `CliError` variant.** Read that rule first, and choose a shape that respects it:
    for example, a small outcome type `run()` returns beside `CliError`.
  - **If no clean shape fits, stop and ask.**
- **Unchanged, by test:**
  - trusted → 0;
  - not trusted → 1, with stdout byte-identical and stderr empty, in prose and JSON;
  - unreadable policy → 1 with `error:`;
  - missing `--key-id` → 2.
- **Control:** after the change, no `process::exit` remains in any command arm of `main.rs`; report the `grep`. A test
  shows the epilogue running on the not-trusted path, through whatever seam the epilogue already offers, or by
  reasoning stated from source if no seam exists.

## 3. `checkout` on a never-sealed branch stops saying the ref "does not exist" (about 30 min)

**Measured on the published 0.52.0 binary** (`setup`, one `commit`, no `seal`):

| command | today |
|---|---|
| `checkout --patch-plan --ref heads/main` (and with no `--ref`) | exit 1, *"ref heads/main does not exist in this repository"* |
| `checkout --snapshot-plan --ref heads/main` | the same |
| `checkout --patch-materialize --ref heads/main` | the same |
| `checkout --snapshot-materialize --ref heads/main` | the same |
| `checkout --plan-only --ref heads/main` | exit 0, `materialization: unpublished-ref`, note *"publish a ref before checkout can target a block"* |
| `tree --ref heads/main` | exit 0, an empty listing |

**The branch exists. It has queued commits and nothing sealed.** This is RFC 147 §2i's class: an unpublished branch is
not absent. stikk released the wording to us (021).

**The ruling:**
- **The four refusing modes keep refusing** (there is no sealed block to plan from or write), but **say what is true**,
  with one shared text. For example: *"heads/main has no sealed block yet (N commit(s) queued) — `prikk seal` publishes
  it"*.
- **The classification is the one `--plan-only` already makes** (`CheckoutMaterialization::UnpublishedRef`), and the
  unpublished-current-branch rule `tree` and `log` use. **Not a third copy.**
- **A ref that truly does not exist still says *"does not exist"*.** Test both.
- **`--plan-only`'s note** uses the user's word too: *"seal"*, not *"publish a ref"*.
- **Exit codes unchanged:** 1 for the refusals, 0 for `--plan-only`.

**Text:** CHANGELOG `### Output changes` (the four refusal lines and the note, before and after), and the
`docs/src/guide/checkout/` pages if they quote the old line.
