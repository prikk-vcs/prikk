## Part 2A — F4: a one-file commit reads every stored blob (90 min, report `0.53.0-step-2-A-f4-design-report.md`)

**What happens today:**
- **The read:** the lifecycle cache's validation (`ValidatedLifecycleCache::from_decoded`,
  `lifecycle_cache/cache_ladder.rs:627`) checks every live node's kind against its blob, through `BlobKindResolver`
  (`lifecycle_cache.rs:46`). That reads each blob's whole frame.
- **The gate:** the store read gate (`test_gates/store_size_independence.rs`) holds the one-file-commit row as a known
  exception, `FollowsContent`.
- **Measured at 0.47.0:** 1, 16 and 64 MiB stored read 1.1, 16.8 and 67.1 MB.

**Answer from source, each with a citation:**
1. **What does the per-commit kind check protect against** that a check at admission does not? List every way a blob's
   kind and a node's recorded kind could disagree when `commit` runs: damage, a crafted import, a bug in an earlier
   writer.
   - The admission paths to compare are `commit`, `seal`, `sync accept`, `bundle import` and `archive import`.
   - For each one, say where the kind is established and checked today.
2. **The options, each with what it still catches and what it no longer catches:**
   - (a) check only the nodes this commit touches;
   - (b) read only the kind, not the whole frame, and say with what integrity (is the kind covered by the frame
     checksum or the object id?);
   - (c) move the check to admission, and trust the validated cache afterwards;
   - any other option the source suggests.
3. **What `verify` still catches, and where,** when a stored blob's bytes are damaged, under each option.
4. **A case table:** each damage or crash state × `commit`, `seal`, `verify`. For each cell, today's outcome and each
   option's outcome. **Every refusal today must still be a refusal under the recommended option,** or the report names
   the cell and asks.
5. **Measured:** the reads of a one-file commit at 1, 16 and 64 MiB stored, today and under the recommended option
   (a prototype), on a release build. The target is the read gate's row moving from `FollowsContent` to `Flat`.

**Constraints:**
- **no format change** (format 8 is RFC 158's);
- **no cache becomes authority** (RFC 162). A cache may speed a check, never replace one;
- **the security property is stated in one sentence and tested:** a crafted or damaged blob whose kind disagrees is
  refused at least as early as today.

## Part 2B — M6: every commit replays the whole queued WAL (75 min, report `0.53.0-step-2-B-m6-design-report.md`)

**What happens today:** `Wal::append_patch` (`wal.rs:197`) calls `replay()` (`wal.rs:221`) to learn four things:
- the tail is clean (no trailing partial bytes);
- no record is damaged;
- the next sequence number;
- whether the last record already matches (an idempotent retry).

It costs about 6.2 ms with 800 queued commits against 4.0 ms with 100 (external review 014). It is small, but linear
and unbounded.

**Answer from source:**
1. **For each of the four facts:** can it come from the WAL's tail, plus a small record kept beside it, without a whole
   replay, **with the same refusals?**
   - RFC 163: a write never buries a crash state.
   - RFC 167: the scan budget.
   - RFC 166: the commit witness, and its acknowledged-commit record.
   - The idempotent retry of an identical last record.
2. **A case table, for both parities** (the case-table rule):
   - **rows, the crash states:** a torn tail, a damaged interior record, a damaged last record, a witness mismatch, a
     concurrent writer;
   - **columns, the operations:** `commit`, `seal`, `rollback-draft`, `doctor`;
   - **each cell:** today's outcome and the design's outcome. An interior damaged record that a tail-only check would
     not see is the cell to answer first.
3. **Measured:** commit time and bytes read at 100, 800 and 3,200 queued commits, today and under a prototype. The
   target is a new **queue axis** in the read gate showing commit reads flat in the queue's length.

**Constraints:** the same as 2A. In particular, **a damaged record anywhere in the queue must still stop `commit`** if
it stops it today. If the design cannot keep that without a replay, say so. That is a ruling, not a choice.
