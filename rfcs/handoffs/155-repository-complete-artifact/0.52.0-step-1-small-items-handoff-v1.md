## Part C — `show <block-id>` resolves each patch at that patch (75 min, report `0.52.0-step-1-C-report.md`)

**From stikk 020.** The owner put it in 0.52.0 step 1 (*"Accepted."*). The finding and the ruling are in
`.git-exclude/reviewed/stikk-020-sealed-block-paths-finding-v1.md`. The summary:
- **Today:** `show <block-id>` resolves every patch's node-addressed operations (`edit-text`, `replace-binary`,
  `change-perm`) against the block's **end** state. The queued form resolves each patch at **that** patch.
- **So in a block of two or more patches, a patch renders differently after `seal`:**
  - a later rename shows the later name;
  - a later delete turns a path into `unresolved_node_id`.
- **Our guide (`docs/src/guide/show.md:40-44`) and `show.rs:236` both say a patch renders the same before and after
  `seal`.**

**The ruling:**
- **The state for each patch:** the block's starting state, then the block's own patches in canonical order **up to
  and including that patch**. The starting state is the mainline parent's for a merge, the sole parent's for a normal
  block, and empty for a root.
- **One fold, two starting points.** The queued form and the block form call the same fold function.
- **The end must agree:** after the last patch, the fold's state equals `lifecycle_state_at(block)`. A test checks
  this on every multi-patch block the matrix builds. **If the source shows a block whose state is not "parent state,
  then its patches in order"** (DC-75 merges, a snapshot checkpoint, the seal's patch-batched rename replay), **stop
  and ask.**
- **The cost** stays one replay per invocation (RFC 142 §4). Measure a 64-patch block before and after.
- **Unchanged:** `unresolved_node_id` stays in the schema, a bare sealed patch id resolves nothing, and `show` writes
  nothing.

**Tests and controls:**
- **stikk's two cases as tests:** rename, and delete, at the block form. Each must match the queued form's output
  byte for byte;
- **queued equals sealed for every patch** in blocks of two or more patches;
- **perturbations, each red:**
  - resolve every patch at the block's end (today's code);
  - fold the whole block for every patch;
  - give the block form its own copy of the fold that differs from the queued form's.

**Text:**
- `guide/show.md`: the table row for a sealed block, and the example *"a block that edits a node and then deletes it"*,
  which now resolves;
- the module and function comments in `show.rs`;
- the CHANGELOG `### Fixed` entry, since this shipped in 0.47.0 contrary to the docs;
- an **Output change** line: in `show-report-v1`, an earlier patch in a multi-patch block can now name a different
  path, or a path where it named `unresolved_node_id`.

**Smoke:** after Part C, `smoke-0.51.0.sh` on a release build, with the count stated. Any change from 317 is
explained line by line.
