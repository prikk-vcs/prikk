## What was measured, on main of 2026-11-12 (`~/.pgtmp/scope058-probe9.log`, `-probe10.log`)

**After `archive import --adopt` of a history whose tip edits text,** each commit reads about 2× the history from the store:
- 42 MB at 20 MiB, and 210 MB at 100 MiB;
- the same on the 2nd and 3rd commit;
- the source repository reads 0.1–0.6 MB for the same commit.

**With a binary tip, only the first commit pays,** about 1×. **A `verify`** (525 MB, once) **or a seal ends it, and nothing
tells the user.**

**The cause, as recorded:** the warm-cache miss on a tip that edits text whose content lives in its edits (DC-65,
`664895b3`). The anchored-text path needs a checkpoint this repository has recorded, and a receiver has none.

## R2: the build (live 2026-11-16; R1 accepted: `.git-exclude/review-request/0.58.0-R-part-1-report.md`) (120 min, stop at 240)

**Rulings on R1:**
1. **Option (ii).** On the miss, the commit runs the root-checking walk (`resolved_parent_state`, the function `verify` runs
   per block and `seal` runs through `write_signed_block`) and records what it confirms, with `record_verified_blocks`. That
   is `verify`'s record, and there is no second one (condition 3).
   - **The walk replaces today's unrecorded 2.0× replay. It never runs beside it.**
   - **Today's commit-path replay** (`replay_lineage_with_materialized_text`) checks no roots, so it **never records.** Only
     the root-checking walk records (condition 1).
2. **`commit` may write `cache/replay-verified-blocks.v1` on a miss.** `commit` already writes `.prikk/cache/` (the commit
   index and the lifecycle state), so one more cache write crosses no line. Write it once per command, in S6's shape.
3. **(i) is not built.** It charges every import, including repositories that never commit. **(iii) is not needed** if (ii)
   closes, because the cost goes.

**First step, before building (it can change the ruling):**
- **Measure the readers on a text-tip receiver:** `tree`, `cat`, `extract`, `diff`, `checkout --plan-only`. N=100, archive and
  bundle, three calls each, on main.
- **A forge never commits.** If a reader pays the whole history per call, (ii) does not help a read-only receiver. **Stop and
  report,** because (i) or a reader-side record would then be in question.
- **If every reader is bounded, say so,** with the numbers, and build.
- **Also measure** whether the walk yields the text the commit needs without a second pass (R1's own doubt). If it needs a
  second pass, state the cost before building.

**It closes on these numbers** (text tip and binary tip; N=20 and 100; `archive import --adopt` and `bundle import --adopt`;
three commits each; against 0.57.0 and against `43fcd06e`):
- **text tip:** the first commit reads ≤ 1.05× the content, and the second and third read ≤ 0.6 MB;
- **binary tip:** no commit reads more than today;
- fsyncs per commit: unchanged, plus at most the one record write;
- peak RSS: not higher than the walk's 12–13 MB;
- **the source repository's commits:** unchanged.

**Tests:**
- the receiver's second commit reads the anchor, pinned by a count of whole-lineage replays (0), not by bytes;
- the record holds only ids the walk confirmed, with the S6 pin's shape (every recorded id is a held Block);
- a receiver whose import adopted nothing (a `remotes/` landing) records nothing for the unadopted chain;
- a damaged received Block: the walk refuses as `verify` would, the commit says so, and nothing is recorded.

**The red controls:**
- record from the unchecked replay: name what catches it, and if nothing does, add the test;
- skip the record: the second commit's replay count returns to 1;
- run the walk and the old replay both: the bytes pin goes red.

**Docs:** what a receiver's first commit costs, in the sync or archive guide, one sentence. **CHANGELOG:** `### Fixed` (a
released cost, measured on 0.57.0 here: 42 MB and 210 MB per commit) and `### Changed` (a commit may record verified blocks).

## R2, amended 2026-11-16, after the readers' measurement (`.git-exclude/review-request/0.58.0-R-part-2-report.md`)

**The readers decided it.** On a text-tip receiver that never commits, `extract` refuses ("no admitted snapshot … pass
`--allow-full-replay`"), and a bare `diff` reads 105 MB per call where the source reads 0.3 MB. **(ii) alone cannot help a
read-only receiver,** and a forge is one. **The owner agreed** (relayed in the report) to R2 being both pieces, with one
record, `verify`'s.

**R2 builds, in this order:**
1. **(i) The adopting imports record what they confirmed.**
   - **Scope:** `archive import --adopt` and `bundle import --adopt`, through one shared place (the callers of
     `begin_adoption`), after the branch is published and the worktree materialized.
   - **The walk:** the root-checking walk (`resolved_parent_state`) over **the adopted chain only**, with one record write in
     S6's shape.
   - **Best effort, and never a refusal.** The objects and the ref are already written, and a refusal after writes is the
     0.44.0 defect.
   - **The architect's one amendment to the agreed recommendation, stated so the owner can object:** if the walk finds a
     block that does not replay to its recorded root, that is a real finding (a block signed by an adopted key that does not
     verify). The import still exits 0 and records nothing from that block on. **It prints one line:** "the imported history
     did not replay cleanly at block <id>; run `prikk verify`". `verify` then names the failure. That line is actionable, so
     it is not the "unactionable warning" the philosophy forbids. Silence would hide what the import just learned.
   - **Measure first,** against 0.57.0: the import's added store reads and wall time. The estimate is +1.0× of store reads
     once (about +105 MB at N=100) and about +5% wall.
2. **(ii) as already ruled.** The commit's miss runs the walk and records. It is the net for repositories imported by 0.57.0
   or earlier, for an import killed before it recorded, and for any other landing.
3. **`extract`'s refusal gains a second typeable way out:** "or run `prikk verify` once".
4. **Not built:**
   - a record written by `extract`, `diff` or `tree`, because a read-only verb writing `cache/` is a larger step;
   - recording for a `remotes/` landing, which is unadopted and would be a claim wider than the mechanism.

**The closing numbers, added to R2's list above:** after `archive import --adopt` and `bundle import --adopt`, text tip, N=100:
- `extract --ref heads/main` succeeds on the first call, at about 142 MB, as on the source;
- **a bare `diff` reads what the source's does, about 0.3 MB.** The 37 MB residual after `verify` that R2's first step found
  is explained or removed in the closing run, not carried.

**The tests, added:**
- the import records only the adopted chain;
- a block that does not replay gives the one line, records nothing from it on, and exits 0;
- a `remotes/` landing records nothing;
- **the red control:** record from before the walk, and name what catches it.

**Not R, and recorded instead** (R2's first step, question 3): `tree`, `cat` and the two-point `diff` read the whole history on
every call, on every repository: 105 MB for `tree` and `cat`, 158–210 MB for `diff`, at N=100. It goes on the ROADMAP as a
candidate.
