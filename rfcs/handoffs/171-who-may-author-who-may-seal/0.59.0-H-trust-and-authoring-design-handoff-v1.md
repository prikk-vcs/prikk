## H1: what is true today, measured (nothing designed). DONE (accepted 2026-11-26; `.git-exclude/reviewed/0.59.0-H-part-1-review-v1.md`)

1. **Key custody:**
   - where `setup` puts each seed, and what each command reads (author, maintainer, both, neither), for every command that signs or
     verifies. **This is a table from the code, and each row is checked on the binary.**
   - **Can an author-only setup exist today?** Set one up (no maintainer seed anywhere prikk looks) and run every command an author needs.
     **Say which refuse, and with what.**
2. **Delivering an author's work:**
   - today only a sealed block under the author repository's own key, which the receiver re-seals;
   - **measure `sync build` → `sync accept` → `sync seal` with the author holding no maintainer seed;**
   - **is a queue of unsealed patches deliverable?** Say what exists, and where it stops.
3. **Trust transitions:**
   - **what `trust maintainer add` and `remove` write** (signed or not, by whom);
   - **what a copy can check** (does `verify` on a copy see that a key was added by an adopted maintainer?);

4. **Least privilege, command by command:**
   - which commands need a seed only to plan (`ref complete --plan-only`, the repair verbs' `--plan-only`, `doctor`), and why;

## H2c: `setup --*-seed-out` into a missing directory refuses before `init` (30 min, stop at 60). DONE (`d383ab54`, accepted 2026-11-27; `.git-exclude/reviewed/0.59.0-H-part-2c-review-v1.md`)

**The defect** (H2b §1, reproduced in the H2b review, D1):
- `setup <repo> --author-seed-out <dir>/a.seed --maintainer-seed-out <dir>/m.seed`, with `<dir>` missing, prints `initialized Prikk
  repository at …`, then fails (`failed to create <dir>/a.seed.key-id: No such file or directory`).
- **It leaves a `.prikk` with no maintainer key adopted.** A rerun finishes it (K6), so nothing is lost. **But a released command starts
  what it cannot finish,** against RFC 148 §2c and the rule that every refusal in a write sequence comes before the first write.

1. **`setup` checks, before `init` writes anything,** that the parent of each `--author-seed-out` and `--maintainer-seed-out` path exists
   and is a directory.
   - **If not, refuse with exit 1 and nothing written,** naming the directory and something typeable that works (e.g. `create it first:
     mkdir -p <dir>`).
   - **Do not create the directory:** where a secret lives, and with what mode, is the user's choice.
2. **`key generate --out <path>` into a missing directory** already fails with nothing written, but its sentence names `<path>.key-id`
   instead of the path given. **Same check, same sentence shape,** before anything is written.
3. **Tests:**
   - for each flag, and for both together: a missing parent, and a parent that is a file. **Exit 1, the sentence, no `.prikk` left, no
     file written;**
   - the `key generate` case;
   - **today's success cases unchanged.**
   - **Red control:** the check removed. The no-`.prikk`-left assertion goes red.
4. **`CHANGELOG.md`:** a `### Fixed` entry (the flags shipped before 0.59.0), and the sentence in `### Output changes`. **Docs:**
   `troubleshooting.md` or `key.md`, wherever `setup`'s seed-out flags are described.
5. **The 15 gates, a final build from the committed tree into a fresh target directory** (both hashes). **One commit.** Report:
   `.git-exclude/review-request/0.59.0-H-part-2c-report.md`.

## H2d: a holder exiting at the look is judged gone; an unwritable seed directory refused before `init` (60 min, stop at 90). DONE (`e74b06cb` + `b02fd1dd`, accepted 2026-11-27; `.git-exclude/reviewed/0.59.0-H-part-2d-review-v1.md`: the `access` check moves into `prikk-store`, H2e)

1. **The lock judge: a holder reaped between `pid_exists` and the `/proc` reads is `Gone`, not `FieldUnreadable`.** This is a released
   defect, and it reaches both the wait and `unlock`.
   - **Fix it in one platform-neutral place:** when the platform read answers `Alive(None)` and `pid_exists` now answers `Some(false)`,
     the answer is `Gone`. (`SystemProbe::read`, or a wrapper every platform's `read_process` goes through.)
   - **On Linux, also:** a `stat` read that fails with `ESRCH` is `Gone`.
   - **Read macOS's and Windows' `Indeterminate` paths and say** whether a process being reaped can reach them. The neutral re-check
     covers them either way.
   - **Tests:**
     - **a seam** (an injected reader) for each window: `stat` → `ESRCH`; a zombie whose `status` cannot be read; an `Alive(None)` whose pid
       is then gone. Each is `Gone`. **A real unreadable field on a live pid stays `FieldUnreadable`.**
     - **A Linux stress test against the real kernel:** a few hundred children, each killed and reaped while the judge looks, as in
       `~/.pgtmp/arch-tools/proc-reap-race.py`. **Never `FieldUnreadable`.** Bound it by count, not time.
   - **Red control:** the re-check removed. The stress test goes red (the window is hit about 290 times in 400) and so do the seams.
   - **`CHANGELOG.md` `### Fixed`:** "a lock whose holder was exiting at the moment `unlock` or a waiting command looked was reported as
     'a field of the holder record is missing or could not be read'". `### Output changes`: none beyond the corrected reason.
2. **`setup --*-seed-out` and `key generate --out` into a directory that exists but cannot be written:** refused before `init`, like
   H2c's missing directory (report §4.2, reproduced).
   - **On unix:** `access(dir, W_OK | X_OK)` in `require_seed_directory`, through `rustix::fs::access`. Add `rustix = { workspace = true }`
     to `prikk-cli`'s unix dependencies: no new crate in `Cargo.lock`. **Say so in the report, with the lock-file diff (none).**
   - The sentence names the directory and the OS's words (e.g. `Permission denied`), and something typeable that works.
   - **The doc comment says `access` uses the real user id** (prikk is never setuid). **Windows is unchanged:** it refuses seed-out paths

   - **Red control:** the `access` check removed.
   - **The nit:** put `prepare_seed_path`'s doc comment back over `prepare_seed_path`, and H2c's over `require_seed_directory`.

## H3a: trust transitions, removal and rotation, designed; every consumer case answered (90 min, stop at 120). DONE (ruled 2026-11-27; `.git-exclude/reviewed/0.59.0-H-part-3a-review-v1.md`: direction accepted; four corrections, H3a2)

## H3a2: the trust design revised under the H3a review (60 min, stop at 90). DONE (ruled 2026-11-27; `.git-exclude/reviewed/0.59.0-H-part-3a2-review-v1.md`: three rulings; written as proposed RFC 172)

**Read the H3a review first** (`.git-exclude/reviewed/0.59.0-H-part-3a-review-v1.md`). It is the input, with H3a's report.

**Deliver the revised design as one document the owner can read start to finish.** The architect then writes it as proposed RFC 172.
1. **Correction 1:** the chain does not close route 3. The author can sign the adoption of the receiver's public key with their own key.
   Say "no" for every option, and why.
2. **Correction 2: design the two relative checks:**
   - **a prefix:** this copy's chain extends one I hold;
   - **a key I already trust:** `trust apply` against the applying repository's own set.
   **Name the command for each.** Re-word every "a copy checks the chain" to say against what. A chain checked only from its own root is
   self-attesting, and is described as such.
3. **Correction 3, (c′):**
   - **every transition is recorded, signed when an adopted seed is present and unsigned otherwise;**
   - **no new refusal on `add` or `remove`, and no `recover` verb;**
   - `trust statement add` and `trust apply` are additions;
   - **`trust maintainer list` shows the chain, each record marked signed by `<id>` or unsigned.**
4. **Correction 4:** **no `verify` warning for an unsigned transition.** Unsigned transitions are info (counted) and are shown in
   `trust maintainer list`. **Blocking only:** a record that does not link, or a claimed signature that does not verify.
5. **Kept from H3a, with the review's notes:**
   - retire and rotate (R1), with **the rollback test** (a ref-state signed after the point that moves a ref back to an old block is not
     counted);
   - `remove` unchanged, plus `--plan-only`;
   - `PRIKK-TRUST-RECEIVED-UNADOPTED` (info), **its exit-code change put to planeter as a question;**
   - `show`/`log` printing `recognized by <id> (<outcome>)`, **with no claim-format change;**
   - **every consumer case, with "without the chain" said per case.**
6. **The price re-stated:** format steps, lines, tests (including the real-kill sweep of a transition's writes), docs, `### Output
   changes`.
7. **Owner flags:** only "a task key bound to a person" and "a deliberate freeze".
8. **The report:** `.git-exclude/review-request/0.59.0-H-part-3a2-report.md`.
