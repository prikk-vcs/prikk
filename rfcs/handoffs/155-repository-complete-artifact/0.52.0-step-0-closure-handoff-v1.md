# 0.52.0 step 0 — the archive's closure follows the store, and the docs say so meanwhile

**Live 2026-10-13, and it is next.** The owner approved the 0.52.0 plan (steps 1–4, *"1-4"*). After the finding below,
the owner chose an early cut (*"(a)"*): **0.52.0 is steps 0–2,** and F4 with M6 moves to 0.53.0.

## Task title and purpose

0.51.0's `archive export` writes a file that its own `archive verify` and `archive import` refuse, for repositories
that `prikk verify` passes. The finding is `.git-exclude/reviewed/archive-closure-finding-v1.md`, and RFC 155 §9.4
carries the amendment of 2026-10-13. The shapes:
- **a repository that ran `sync accept`:** a recognition claim references blocks the repository does not hold;
- **a text file edited, sealed, then deleted:** a patch references a blob that was never stored (DC-65).

Both fail with *"… references `<id>`, which this archive does not carry"*.

**The cause:** the archive's closure pass (`archive/verify.rs`, `extract_references`) requires every reference to be
carried. The store requires less, by design (`verify/reachability.rs:15-30`). **The rule now:** a missing reference is
damage only if the store's own `verify` requires it to resolve.

## Part C — closure follows the store (90 min, report `0.52.0-step-0-C-report.md`)

1. **The table first, from source, written into the report:**
   - every object type × every reference `extract_references` yields;
   - for each, the store's rule: required to resolve (and by which check: `verify_block_payload`,
     `ensure_ref_target_valid`, `ensure_required_attestations_present`, queued-patch connectivity) or never checked
     (the claims rule, a sealed patch's blobs, a received ref's previous state).
   - **If a row is unclear, stop and ask.** Do not choose.
2. **One predicate, shared.** The archive asks the store's own rule which references must resolve. It must not keep a
   second list. If the store's rule lives in several functions today, give it one home that both call. That is a
   refactor of `verify`'s classification: **the store's own verify output must be byte-identical before and after,**
   on the matrix (`matrix.py` v6, both depths).
3. **The round trip, the test that was missing.**
   - For every state the matrix builds where `prikk verify` exits 0: `archive export`, then `archive verify` exits 0,
     then `archive import` into a fresh repository, whose `prikk verify` gives the result the source gave (allowing
     the expected *"not adopted"* rows).
   - At the least, these shapes as named tests: `sync accept`; edited, sealed, then deleted; merge; rename;
     restoration; tag; closed branch; received bundle pointer; queued work refused at export as before.
4. **Controls, each shown red:**
   - an archive with a required reference removed (a block's parent, a RefState's target) is still damage, by name;
   - **perturb the shared predicate:** make it require a claim's references, and the store's test and the archive's
     round-trip test both go red;
   - the two shapes above, run on 0.51.0's binary, fail. That shows the test reaches the defect.
5. **Text:**
   - the CHANGELOG's 0.52.0 section gets a `### Fixed` entry (shipped behaviour): what failed, for whom, and that an
     archive taken with 0.51.0 imports with 0.52.0 if its source verified. **Check that last claim:** a 0.51.0-written
     archive of each shape, verified and imported by the fixed binary;
   - Part W's limitation becomes a *"Fixed in 0.52.0"* line;
   - the docs grep for *"does not carry"* and for closure wording.
6. **Gates:** all 14, on the final commit, with each exit code. Plus smoke-0.51.0.sh on a release build, 317 ok.

**Security note:** this round loosens an acceptance check, so the round must loosen it exactly to the store's rule,
not past it. A reference the store requires is still refused. The controls in item 4 show it.
