## What is true today, to be re-measured in B′a

- **Two walks.** `bundle preview` lists the class and maintainer-signature refusals, and says so (0.57.0). `bundle import`'s
  pass 1 raises more: an author-key conflict, the signature bound, the store's write decision, AUTHOR signatures, structural
  problems.
- **The preview has `--max-object-bytes`, and neither `--adopt` nor `--allow-non-fast-forward`.** So a preview can read clean
  while `import --adopt` refuses for an adoption reason.
- **Since P3b, `bundle import`'s pass 1 runs under the active lock and the container locks** (lock A), so a refused import
  writes nothing. **`bundle preview` takes no write lock,** and keeps it that way (the 0.55.0 3b-iii ruling).
- **The preview's peak follows the content** (P4a: about 106 MB for 100 × 1 MiB, the replay's file contents, for its impact
  report). The import's is flat at 12 MB.

## B′a: re-measure, then design (nothing built)

1. **Measure, release builds, against the published 0.57.0 and `f2f935a4`:**
   - which refusals each command raises on the same refused bundles: one per refusal kind the import's pass 1 has, plus an
     adoption refusal;
   - each command's peak RSS and wall time on b100 and on the 158 MiB bundle of condition 4 (or say which you used).
2. **The design against the six conditions.**
   - **Condition 1, structural.** One function decides and returns a plan, and holds no handle that can write. Name its
     signature.
     - **The lock is the caller's:** the import takes lock A around the decision, then applies the plan under the same
       hold. The preview calls the same function with no lock, and reports against the repository as it reads it now.
     - **Say what changes for the decision without the lock:** a concurrent writer can change what the import would then
       decide. That is "now", as condition 3 says.
     - The control: a write inserted into the decision fails to compile, or fails a test.
   - **Condition 2:** the preview accepts exactly the import's decision-changing flags. List every flag `bundle import`
     takes, and which ones change the decision.
   - **Condition 3:** the sentence on what is not previewed (pass 2's per-object checks, I/O failures) goes in the help and
     the reference, **never in each run's output.**
   - **Condition 4:** the import's peak must not rise (re-measured). The preview now verifies every signature, so state its
     time. **The preview's replay for its impact report,** whose memory follows the content: say whether it stays, and
     whether it shares anything with the decision.
   - **Condition 5:** the re-delivery record (140 bytes per `already-at-tip` import) is skipped only when the decision read,
     under the held lock, a last entry naming the same RefState. **If that needs a branch of its own, drop it.**
   - **Condition 6:** `archive import` has no preview. Say whether the shared walk would extend to it. It is not built.
3. **What changes for the user,** listed as the release notes would say it:
   - the preview's new refusals (it now says what the import would refuse);
   - its new flags;
   - its time.

   **Check consumers' fixed strings:** stikk reads the CLI, so does a preview's output or its `--format json` change shape?

## B′b: live 2026-11-17, after the architect read B′a (`.git-exclude/review-request/0.58.0-B-prime-part-a-report.md`) (120 min, stop at 240)

**Build B′a's design** (`bundle/decision.rs`, `decide()` returning an `ImportDecision` with every refusal in the import's order;
the import raises the first with today's `PrikkError` and sentence; the lock is the caller's; `ObjectReadSnapshot::check_write`
appends nothing), **with these rulings:**

1. **The control (condition 1): the test form, ordered by strength.**
   - **The primary witness is behavioural:** `decide` over every row of B′a's matrix, the `--adopt` rows and the clean path
     included, leaves the repository byte-identical (locks and caches included). The red control inserts a write.
   - **The structural part:** `decide`'s signature names no `ObjectWriteSession`, no lock guard, no signer.
   - **The source scan is kept only as a secondary witness, and its limit is stated in its comment:** it matches names, and a
     writer not on its list passes it ("classify by context, not by spelling").
   - **The façade is not built.** Its helpers would need the layout too, so it would not be structural either, without the
     same audit.
2. **Condition 5: dropped.** The skip would flip `pointer_updated` on every `already-at-tip` re-delivery, a reported field,
   for 140 bytes that `compact` reclaims.
3. **The ids: one vocabulary.**
   - Where `bundle import`'s `refusal-v1` already prints an id for a refusal, the preview's `import_refusals[].id` for it is
     **the same id.**
   - New names (B′a proposed `author-key-conflict`, `adoption-refused`, `admission-refused`, `store-refused`,
     `received-index-damaged`) only where the import has none. Each is checked against the shipped documents
     (`refusal-v1`, `verify-report-v1`, `log`, `bundle-preview-v1`), so that no name means something else elsewhere.
   - **List the mapping in the report.** The 0.59.0 JSON round (J) revisits them.
4. **`--adopt` on a preview reads no seed.** That is least privilege: a read-only command does not open a secret.
   - The preview takes the **configured** maintainer key id, the one `prikk key status` reports, and reads that key's
     **public key from this repository's trust policy.** It then judges standing exactly as `verify_signer_trusted` does
     (key id and public key).
   - **A key id that is not adopted here** is the import's own refusal sentence.
   - **The help and the reference say:** "a preview does not read your signing seed; `bundle import`, which signs, is what
     proves the configured key id is the seed's".
   - **If the configured id cannot be read without the seed,** say so and stop. That is inklkunn's ask 1 again, and the same
     answer serves both.
5. **`bundle verify` keeps its lean walk** (offline, no repository). Two walks remain, and that is stated in the reference.
6. **The import now collects every refusal and raises the first.** Accepted. State the extra work a refused delivery now does
   (a few signature verifications), measured on one refused b100.
