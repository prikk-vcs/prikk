## Part 2 — A1: `prikk extract` for a ref or a block id (about 90 min, report `0.54.0-step-3-part-2-report.md`)

**The command:** `prikk extract --ref <ref|block-id> <dir>`. The CLI form follows `cat` and `tree`; propose the exact
syntax in the report.

1. **Anchoring (ruling 2):** the admitted anchor only (`AnchorTrust`, as `VerifiedWorktreeWrite`). Otherwise it
   replays from genesis.
   - **It never uses `Anchoring::ReadOnlyReport`.**
   - `cat` and `tree` keep theirs.
2. **The pre-walk:** Block envelopes only, measuring the distance to the nearest **admitted** snapshot. Past
   `CHECKPOINT_CADENCE`, it refuses by name, giving the distance found and `--allow-full-replay`. It runs before any
   Patch or Blob is read.
3. **Streaming (ruling 1):** every file at the anchor is written straight from its blob id, unless a later block applies
   `EditText` to it.
   - Binary files created or replaced after the anchor are written from their new blob id.
   - **Only text files edited after the anchor are held,** with their base.
   - **Say from source how a file whose path is renamed after the anchor is handled.**
4. **Write safety:**
   - `validate_no_path_collisions` over the point's paths, before the first write;
   - the target must not exist;
   - a temporary sibling `<dir>.prikk-extract-tmp`. If it exists, refuse and name it (ruling 3);
   - `rustix::fs::renameat_with(..., RenameFlags::NOREPLACE)` on Linux and macOS;
   - `MoveFileExW` without `MOVEFILE_REPLACE_EXISTING` on Windows, **pinned by a Windows test that CI's Windows job runs**
     (ruling 4);
   - **all-or-nothing:** a refusal or error leaves neither the target nor the temporary sibling, except after a hard
     crash.
5. **`provisional: yes|no`,** worded as `checkout` words it.
6. **Never writes into the repository:** no lock, cache, marker or worktree write. A test asserts the `.prikk/` tree is
   byte-identical before and after.
7. **Tests and controls:**
   - **output equal, byte for byte, to `cat --output` of every path that `tree` lists at the same point,** across text,
     binary, edited-after-anchor, renamed and deleted files, and with no extra files;
   - the collision refusal, shown red by removing the check;
   - the no-replace rename, shown red with a plain `rename` (Linux);
   - the pre-walk refusal, shown red by removing the bound;
   - **the trust rule:** a crafted unadopted-key block whose snapshot disagrees with its patches. `extract` writes what
     the patches give (full replay), not the snapshot. Shown red by passing `ReadOnlyReport`.
