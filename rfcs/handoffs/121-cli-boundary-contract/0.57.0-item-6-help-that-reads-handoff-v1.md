## What is true today (measured by the architect, 2026-11-10)

- **`prikk --help` prints 101 lines,** with 85 command lines for the 36 entries of `crate::commands::COMMANDS`. There
  are no groups; each line is a full synopsis plus description; the longest is 622 columns.
- **`prikk help` fails:** "error: unknown command: help".
- **`output/help.rs` holds no command text of its own (RFC 118 stage 1),** and per-command help derives from the
  registry (RFC 121). The RFC 118 §8 doc-coverage gate binds `COMMANDS` to the documentation.

## The part

1. **Two fields on each `COMMANDS` entry,** in the same table and never a second one:
   - `group`, an enum, so a misspelt group cannot compile;
   - `summary`, one line, about 60 columns at most, that is **true of the whole command**.
2. **Top-level help** (`prikk`, `prikk --help`, `prikk -h`, `prikk help`):
   - the groups in the proposal's order, one line per command (name and summary);
   - a `Usage:` header that also names `prikk help <command>`;
   - a closing line naming `https://prikk.org/docs/`;
   - nothing longer than 80 columns. A test asserts this.
3. **`prikk help <command>` is an exact alias** of `prikk <command> --help`: one code path, identical bytes, the same
   exit code. `prikk help <unknown>` is the unknown-command error. The per-command help (`help_lines`) is unchanged.
4. **Every summary is checked against what the command does.** Read its own help and its guide page; do not copy the
   proposal's draft. The architect's first draft had four false summaries (`received`, `compact`, `format`,
   `config`). The report lists each summary beside the sentence of the reference it rests on.
5. **New command `uncommit`** (S5b) appears under "Record your work", beside `commit`.
6. **Tests:**
   - every entry has exactly one group, and every group is non-empty;
   - the top-level width limit;
   - the alias's byte identity, for every command;
   - the unknown-command error through `help`.

   Tests that assert top-level help lines (for example L2b's `unlock` URL test) move to that command's own help.
   Give each new assertion a red control.
7. **The gates:** the RFC 118 §8 doc-coverage gate must stay green, and still bind `COMMANDS` to `commands.md`. Say in
   the report how the new fields relate to it, and whether `commands.md` should show the groups. If it should, it
   derives them, never transcribes them.
8. **CHANGELOG** `### Changed`: the top-level help is now a grouped summary; `prikk help [command]` works; `prikk
   <command> --help` is unchanged.
