## The rule

1. **The stored claims are enumerated once per batch,** and every per-claim check reads that one set: the order
   ambiguity, the parent check, and the plan's mirror.
   - **Before relying on it, show that the set cannot change during the batch, or that a change cannot change any
     refusal.** Can a `sync accept` record a claim while a `sync seal` runs? Which lock each takes decides it.
   - If accept can add a claim mid-batch, either the batch reads the set under a lock that excludes accept's claim
     write, or the design shows that a claim added mid-batch cannot create an ambiguity the per-claim enumeration would
     have caught. **If neither holds, stop and ask.**
2. **The ref's history is extended, not re-walked.** After a claim's Block is published, the batch's history set gains that
   Block, instead of `ref_history` walking from the tip again.
   - **Show that the ref cannot move between claims** under the locks `sync seal` holds, or say what catches it if it
     does. The publication's CAS refuses a moved ref today: confirm that, and name the test.
3. **One reader for each.** The batch-scoped sets live where the fold's running state lives (`batch_fold`, or beside it),
   not as a second cache.
4. **Refusals are unchanged.** Every row of the S2a checklist still fires with the same message at the same claim. Name any
   that moved.

**It closes on the numbers.** Re-run S2b's measurement: the same artifacts and scripts, base and noncur, 250 and 1,000 claims.
- **The claim container and the block container fall to linear:** state the bytes per claim at 250 and at 1,000. They
  should be about equal.
- **The planeter total:** state it, and the per-file table again. That table is S4's baseline.
- **The binaries shape** must not regress (259.5 MB at 100 MiB).
- **fsyncs:** unchanged or fewer.
- **The corpus** is green, all nine shapes. **The two-build check** (`s2b-two-build.sh`) is IDENTICAL at 100 MiB, 250 and
  1,000 claims.

**The red controls:**

  red (name it);
- skip the history extension, so a later claim's parent check uses the old history: name what goes red;
- add a claim mid-batch: whatever rule 1 concluded, a test holds it.
